# Returning small constructors by value (struct return): design

Status (2026-09-25): implemented and on by default (`--directive
nostructreturn` turns it off), after the measurements in "Results". Tracks
`TODO.md`'s "constructor return values are always heap cells" item.

## The problem

A function that returns a constructor always builds a heap cell, even
when its caller only switches on the result and takes the fields out.
The dominant case is upstream's `Core a = IO (Either Error a)`: `IO` is
already gone from the IR (no `MkIORes` survives to `dumprcexpr`), so a
`Core` action returns a bare `Left`/`Right` cell, and its caller
destructures it on the spot.

Reuse analysis already softens this. When the caller rebuilds a
constructor of the same size (`Left e => Left e`, `Right x => Right (f
x)`), it builds into the cell it just received, so a chain of such
functions allocates once at the bottom and frees once at the top, not
once per level. What is left is that one malloc/free pair per chain, and
at every level a uniqueness check (`reuseOffer`), its `dupOnShared`
branch and the reads and writes of the cell itself.

## Scope: one fixed C type, at most one field

```c
typedef struct {
  int64_t tag;
  union { IDRIS2RC2_Value *p; int64_t i; double d; } f0;
} IDRIS2RC2_Ret1;
```

One type for the whole program, in the runtime header. No per-type
layouts and no `CFType`: `Core.CompileExpr.CFType` is upstream's
type, and its `CFStruct` already means "pointer to a C struct" in every
backend (Chez renders it `(* name)`, RefC and rc2 `void *`), so it is the
wrong carrier for a compiler-generated by-value layout.

Sixteen bytes, so it comes back in `rax:rdx` under the SysV x86-64 ABI,
with no memory round trip: the union is one eight-byte word, classed
INTEGER as a whole. A Boxed field lives in `f0.p`, and a nullary
constructor leaves it `NULL`. A native field (`Right 3`) lives unboxed in
`f0.i` (every integer type, widened) or `f0.d` (`Double`) when the
struct's layout says so; see "Native fields" below.

A later extension to wider constructors would add `IDRIS2RC2_Ret2` and so
on, or per-type unions of structs with a common leading tag. The
measurements below say that is not worth doing first.

## Measurements

### Static counts (idris2-lsp, final `dumprcexpr`, 2026-09-25)

A throwaway tool in the session scratchpad parsed the dump and counted,
for a field limit `k`, the functions whose every tail is a constructor
with at most `k` fields, a crash, or a tail call to another such
function (a greatest fixpoint, restricted to functions that reach at
least one constructor). Call sites of those functions are then split by
what the caller does with the result.

Of 20,864 functions, 9,907 end in a constructor somewhere, and 4,959
`let v = call ...; case v of` pairs exist in total.

| k | functions | call then `case` | tail calls | other calls |
|---|---|---|---|---|
| 0 | 66 | 0 | 2 | 3 |
| **1** | **8,039** | **3,648** | **3,688** | 4,782 |
| 2 | 9,539 | 3,896 | 4,170 | 10,831 |
| 3 | 10,124 | 3,949 | 4,232 | 11,991 |

- `k = 1` already covers 74% of all call-then-`case` pairs. Going to
  `k = 2` adds 7% more, and makes the struct 24 bytes, returned through
  memory.
- 2,627 of the 3,648 cased sites (72%) sit inside a function that is
  itself eligible, so the struct keeps travelling up the chain.
- 3,312 of the 3,648 (91%) rebuild into the received cell today
  (`reuse=`), which is what the reuse analysis above already saves.
- The main reasons a constructor-returning function is not eligible at
  `k = 1`: a 2-4 field constructor tail (about 2,200 functions), and an
  `apply` tail whose result shape is unknown (790).
- Tail calls between eligible functions form no cycle at all (2,711
  functions carry 3,481 such edges, Kosaraju finds no strongly connected
  component and no self edge: `Loop` and `MutualLoop` have already
  turned those into `goto`s). See "Tail calls" below for why this
  matters.

### Run time (hand-written model)

`step d x` recurses `d` levels; every level cases on the level below
and rebuilds the same `Either String Int`. rc2's own generated C is the
baseline; the model replaces only `step` and its caller with a
hand-written struct-return version (same results). Best of three,
nanoseconds per outer iteration (one chain of depth `d + 1`).

| `-O2` | cell + reuse | struct | saved |
|---|---|---|---|
| small payload, d=1 | 129 | 88 | 41 (32%) |
| small payload, d=2 | 136 | 95 | 42 (30%) |
| small payload, d=4 | 156 | 106 | 50 (32%) |
| small payload, d=8 | 188 | 129 | 59 (32%) |
| heap `Int` payload, d=1 | 133 | 83 | 50 (38%) |
| heap `Int` payload, d=8 | 403 | 334 | 69 (17%) |

About 40 ns per chain (the malloc/free pair and the cell's
initialisation) plus 2-3 ns per level (the uniqueness check and the
cell traffic). The model also drops `idris2rc2_trampoline` around the
calls, which accounts for part of the per-level figure. Dynamic counts
on a real workload have not been measured.

## Representation in the IR

`RRet1` is a new `Rep`: it marks where a struct lives, and one new node
builds one. Everything else is an existing node.

| what | IR | new? |
|---|---|---|
| a function returns a struct | `MkRCFun ... (retRep = RRet1)` | the Rep only |
| a call to such a worker | `RAppNameRep ... (retRep = RRet1)` | existing node |
| holding the result | `RLet v RRet1 (callRep ...) body` | existing node |
| switching on it | `RConCase v alts`, `v`'s Rep being `RRet1` | existing node |
| passing it up unchanged | `RV v` in tail position | existing node |
| **building one** | **`RRetPack : FC -> (con : Name) -> (tag : Int) -> Maybe RCLocal -> RCExp`** | **new** |

`RRetPack` is valid only in a tail position of a function whose
`retRep` is `RRet1`. It consumes its field's reference exactly as an
`RCon` argument does; a nullary constructor has `Nothing` (`f0 = NULL`
in C). A static constant constructor tail (`#Left@0([#"neg"])`) becomes
an `RRetPack` whose field is that static argument.

Building uses a node of its own rather than giving `RCon` a second
meaning in that position, for three reasons:

1. An `RCon` whose meaning depends on where it sits would change meaning
   silently when a pass moves it out of the tail or copies it into a
   Boxed context. That is the same trap `RMemoize` set for passes with a
   catch-all clause.
2. `RCon` carries `reuse=` and constructor-name handling a struct never
   needs, and every reader (Emit, the lint) would need exceptions for it.
3. `retpack` in a dump says at a glance that nothing is allocated.

The cost is one clause per exhaustive `RCExp` match. Only four passes
run after DualABI: `DeadCode`, `DupMerge`, `DeadVars` and the final
dup/drop cancel. Each gets an explicit clause, not a catch-all fallback.

Switching stays an `RConCase`: its alts already fit (a constructor name,
a tag, one field), and Emit already keeps each local's Rep, so the
scrutinee's `RRet1` is known from its `let`.

A local of `RRet1` may only be used in one of three ways:

1. as the scrutinee of the `RConCase` that is the body of its own `let`
   (after RC wrappers), with no other read of it;
2. returned as-is (`RV v`) from a tail position of a function whose own
   `retRep` is `RRet1`;
3. named by the RC operations `annotate` placed on the cell it replaces
   (`drop`, `free`, `reuseOffer`, `releaseReuse`, `reuse=`), which the
   rewrite below removes or turns into operations on `f0`. None of them
   survives the rewrite.

Any other use keeps the call on the Boxed wrapper.

An alt that rebuilds the constructor it matched with the field it
received (`Left e => Left e`) returns `v` itself instead of packing a
new struct. That is the struct counterpart of today's `reuse=`.

The `step` model from the measurements above would dump as:

```
def {idris2rc2_worker_Main_step:2}  (fun args= ["v68:Native Int", "v69:Native Int"] ret= Ret1 worker=True)
  case v68 of
    0 ->
      cmp <Int [v69, #0]
      then
        retpack Prelude.Types.Left tag= 0 [#"neg"]
      else
        let v70 : Boxed = ...
        retpack Prelude.Types.Right tag= 1 [v70]
    _ ->
      let v72 : Ret1 =
        callRep {idris2rc2_worker_Main_step:2} ["Native Int", "Native Int"] -> Ret1 [v73, v74]
      case v72 of
        Prelude.Types.Left [datacon] tag= Just 0 args= [v75] ->
          v72
        Prelude.Types.Right [datacon] tag= Just 1 args= [v76] ->
          let v77 : Boxed = ...
          drop [v76]
          retpack Prelude.Types.Right tag= 1 [v77]
```

`dumprcexpr` prints the new Rep as `Ret1` and the new node as `retpack`.
The `.rcexpr` parser lives in
`libs/rc2base/src/Language/RCExpr/Parser.idr`, which another agent is
currently editing; the parser change (one more Rep token, one more node)
has to be coordinated with that work before `rcexpr-lint` can read such
dumps.

## Pipeline placement: a new DualABI stage

Struct return is another worker/wrapper split, so it belongs in
`Compiler.RC2.DualABI` and reuses its machinery:

- **Eligibility** (read-only, like DualABI's Stage 2): the greatest
  fixpoint above, over the post-`Loop` defs DualABI already sees. A tail
  is acceptable if it is:
  - an `RCon` with at most one argument and a `Just` tag;
  - a static constant constructor (`RCConstCon`/`RCEmptyCon`) of at
    most one field;
  - an `RCrash`;
  - a non-lazy `RAppName`, or an `RAppNameRep`, to another eligible
    function;
  - `RV RCNull`. Phase 1 folds Nil/Nothing/Z/MkUnit into `RCNull`, all
    tag 0, but an erased value is `RCNull` too, so such a tail is
    accepted without counting as a constructor.

  The function must also reach at least one real constructor tail. `MutualLoop`'s
  merged functions and CAFs (bodies under `RMemoize`) are excluded, and
  so is any member of a tail-call cycle among eligible functions. That
  set is empty on idris2-lsp today, but the check keeps the "Tail calls"
  argument true by construction.
- **Worker synthesis**: an eligible function gets a worker with
  `retRep = RRet1`. Its parameters keep whatever DualABI's parameter
  analysis decided, so native parameters and struct return combine in
  one worker. The wrapper keeps the Boxed signature and materialises the
  cell (below).
- **Call-site rewrite**: DualABI's Stage 4 walk gains one more case: a
  `let v = call f ...` whose body cases on `v` (use 1 above), or a tail
  call from inside another `RRet1` worker (use 2), targets `f`'s worker
  with `retRep = RRet1`. Every other call keeps using the wrapper.

It runs after RC annotation and Reuse, like the rest of DualABI, so the
worker bodies and call sites it rewrites already carry `dup`/`drop`/
`reuseOffer`, and the rewrite has to translate those (next section). The
passes after DualABI (`DeadCode`, `DupMerge`, `DeadVars` and the final
dup/drop cancel) need an `RRet1` case wherever they inspect Reps or
scrutinees.

## RC at a struct scrutinee

With a cell, a case alt borrows its fields from the scrutinee, and
`annotate`/Reuse arrange for the alt to take its own reference (`dup`)
before the cell is released. With a struct, the struct *owns* its one
field outright, and there is no cell to release or reuse. The struct is
therefore always in the state a unique cell would be in, and the rewrite
takes the unique path of every reuse construct statically:

| on the cell `v` | becomes, for a struct `v` |
|---|---|
| `drop [v]` | `drop [f0]`: the struct's own reference to its field |
| `free v` | nothing (no shell to free) |
| `reuseOffer v dupOnShared= ds dropOnUnique= us` | `drop us`; the fields keep the struct's references |
| `releaseReuse v` | nothing |
| `con C [...] reuse= v` | a fresh `con C [...]`, or an `RRetPack` when it is a tail of an `RRet1` worker (or `v` itself when it rebuilds the matched constructor with the same field) |

`f0` needs a local even when the alt binds the field as `_` (DeadVars
renders a dead field that way), so the rewrite binds it to a fresh
local. A `dup f; ...; drop [f0]` pair that results on the same field is
left for DupMerge's existing cancellation to remove.

The cell version's shared path (`dupOnShared`) disappears entirely,
because a struct is never shared.

## Emission

- `let v : Ret1 = callRep f ...` renders
  `IDRIS2RC2_Ret1 var_v = worker(...);`, with no `idris2rc2_trampoline`
  around it. A struct-returning worker never returns a thunk (next
  section).
- An `RConCase` on an `RRet1` scrutinee switches on `var_v.tag`; its
  field local is `var_v.f0.p`, or `var_v.f0.i`/`.d` for a native field
  ("Native fields" below).
- A tail value of an `RRet1` worker renders by shape:
  - `RRetPack C tag (Just x)` renders
    `return (IDRIS2RC2_Ret1){ tag, { .p = x } };`, or `.i`/`.d` for a
    native field.
    Worker synthesis turns the function's constructor tails into
    `RRetPack`s: an `RCon` of at most one field, and a static constant
    constructor, whose static field is immortal and needs no dup.
  - `RRetPack C tag Nothing` (a nullary constructor) returns
    `{ tag, { .p = NULL } }`.
  - A tail call to another `RRet1` worker renders `return worker(...);`.
  - An `RRet1` local renders `return var_v;`.
- The wrapper materialises the cell with an ordinary `RConCase` over the
  worker's result whose alts are plain `RCon`s. Its constructor set is
  the union of the function's own constructor tails and its callees'
  sets. This way `NIL`-as-`NULL`, static nullary constructors and
  constructor names all go through the existing `RCon` emission, so the
  wrapper's output is exactly what the original function returned.

## Tail calls

Today a tail call that `Loop`/`MutualLoop` did not turn into a `goto` is
emitted as a saturated closure returned to the caller's trampoline
(`tryBuildClosureInto`). That closure is another heap allocation, and it
exists to bound C stack growth through chains of tail calls of unknown
depth; see `doc/dual-abi.md`'s Stage 4 "Scope" for why DualABI never
rewrote tail calls.

An `RRet1` worker cannot return a closure, so its tail calls into other
`RRet1` workers become direct C calls. This is safe because eligibility
excludes members of tail-call cycles: without a cycle, the chain of
nested direct tail calls from any entry is at most as long as the
longest path in an acyclic graph of eligible functions, a static bound.
Recursion through non-tail calls grows the C stack exactly as it does
today. At `-O2` (the default since `ff1093d`) gcc usually turns these
same-signature returns into sibling calls anyway, but correctness does
not rely on that.

As a side effect, the 3,688 tail calls between eligible functions no
longer allocate a closure each.

## Order of implementation

1. **Eligibility dump only.** Add `RRet1` to `Rep` and the runtime
   typedef, and compute eligibility, printed by `--directive
   dumpdualabi`. Check it against the scratchpad tool's figures on
   idris2-lsp. No code changes behaviour. Done: `structReturnEligible` in
   `Compiler.RC2.DualABI`; each line of the `.dualabi` dump ends in
   ` ret1` for an eligible function, after a count line. On idris2-lsp
   it accepts 8,005 functions. The scratchpad tool's 8,039 differs mainly
   because it keys functions by their printed name, and distinct
   `Name`s print alike (16 different definitions print as
   `Core.Context.full`).
2. **Worker and wrapper.** Synthesise the `RRet1` worker and the
   materialising wrapper; every caller still calls the wrapper. This
   exercises the worker's tail emission and the wrapper's materialisation
   on every eligible function while the call sites stay unchanged.
   Done as `applyStructReturn`, a pass of its own right after Stage 3a's
   native worker synthesis, so a function that already has a native
   worker keeps it and only its `retRep` changes. It had to include
   step 4: a struct worker's tail call must yield a struct, so it goes
   to the callee's struct worker directly. Two details the plan did not
   foresee:
   - `structReturnPlan` records how each function built each constructor
     it returns, by tag, and the wrapper rebuilds exactly that: a nullary
     tail is copied verbatim (`RCNull` for Nothing/Nil stays `NULL`, an
     `RCEmptyCon` stays a tagged pointer). A function whose reachable
     constructors disagree for one tag is left out.
   - Until step 3, a function with native parameters loses Stage 4's
     native call sites: its wrapper no longer has the single-call shape
     `workerTable` looks for, so its callers box their arguments again.
     Step 3 closed this gap.
3. **Cased call sites.** Rewrite use-1 sites with the RC table above.
   Done as `structSites`, run on every body before `packTails`. A site
   is left alone when the struct would be read any other way, when the
   `case` has a default that mentions it, or when an alt has more than
   one field (a constructor the callee never returns). It also closes
   step 2's gap: a call to a worker with native parameters whose result
   is *not* switched on reaches the worker too, and builds the cell
   right there, so it keeps passing its arguments natively.
4. **Tail calls between workers.** Rewrite use-2 sites to direct calls.
5. **Measure.** Measured 2026-09-25, see "Results" below. Static metrics, the new benchmark and `verify.sh`, all
   with and without a `nostructreturn` directive (`structreturn` was
   opt-in until 2026-09-25; the directive flipped when it went default,
   documented in `directives.md`).

## Results (2026-09-25)

`tests/BenchStructReturn.idr` (a four-level `Either` chain, five
million calls, best of five): 674 ms without struct return, **475 ms**
with it (about 30% faster), identical output. valgrind counts 10.0M
allocations without and **5.0M** with: the `Either` cell is gone
entirely; the one allocation left per call is `mod x 64` boxing its
operand, unrelated to this work.

idris2-lsp, final `dumprcexpr` (C generation is not reached, see
`TODO.md`), against the default pipeline:

| | default | `structreturn` before `prunePlan` | `structreturn` |
|---|---|---|---|
| definitions | 22,522 | 29,609 (+7,087 workers) | 22,757 (+235) |
| struct workers | 0 | 7,844 | 644 |
| `con` | 53,957 | 49,167 (−8.9%) | **51,175** (−5.2%) |
| `retpack` | 0 | 17,643 | 3,679 |
| `reuseOffer` | 25,765 | 17,865 (−31%) | **17,865** (−31%) |
| `let ... : Ret1` | 0 | 13,011 | 5,929 |

`prunePlan` (below) keeps every call site that gains: the `reuseOffer`
count, one per rebuilt cell a caller switched on, is unchanged. What it
drops is the workers nobody calls directly, and the cells their
wrappers rebuilt.

`rcexpr-lint` finds no anomaly in either dump. `verify.sh` passes with
and without struct return on every test, valgrind included.

idris2-missing-containers (`test/src/Main.idr`, a hash-map benchmark,
run from the package root; five alternating runs, the first of each
left out as warm-up): wall time 12.13 s without, 12.29 s with (+1.3%),
before `prunePlan`;
every phase the program times itself within noise or slightly slower.
Only five functions qualify there, and none has a direct call site that
benefits: they are lambdas (`{read:0}` and the like) passed as closures,
so every call goes through `apply`, reaches the wrapper, and pays one
extra call and a rebuild of the cell. So a function now gets a struct
worker only when some caller gains from it (`prunePlan`): a call whose
result is switched on at once, or a tail call from another function
that keeps one. Native arguments alone don't count: Stage 4 already
passes them natively to the Boxed-returning worker. Dropping a function
can leave another planned function tail-calling it with no struct to
return, so the cut repeats until nothing changes.
With it, no function qualifies on idris2-missing-containers any more,
and the program times as without struct return (12.11 s and 12.12 s);
`BenchStructReturn` is unaffected (667 ms and 468 ms).

## Native fields (2026-09-26)

`RRet1` carries a layout: the tags whose field the struct holds
natively, and as which type (`Ret1:1=Int` in a dump). A tag is native
only when every tail building it delivers the same fixed-width integer,
`Char` or `Double` -- a native local or a literal -- in this function
and in every function the struct passes through unchanged by a tail
call: tail-call neighbours share one layout (`ret1Layouts`), meeting to
Boxed on any disagreement.

- A pack stores the field with `rcVarToNativeC` into `f0.i`/`f0.d`.
- An alt on a struct binds a native field as a native C local and
  records it in Emit's `RepMap`, so a Boxed use boxes it afresh the way
  any native local is boxed.
- At a rewritten call site such a field owns nothing, so every `dup`,
  `drop` and `postDrop` of it goes (`dropOwnership`); the `drop` of the
  struct becomes nothing for that tag.
- The wrapper and a cell built in place box it through their ordinary
  `RCon`.

On idris2-lsp almost nothing qualifies: of 3,679 packs, 5 have a native
local and 73 an integer literal as their field; `Core` returns terms and
names. Numeric chains are what gain: `tests/BenchStructReturnNative.idr`
(`BenchStructReturn` with every payload above the small-int cache) runs
1,723 ms without struct return and **864 ms** with it, and allocates
50.0M times without and 20.0M with. The worker allocates nothing; what
was left was `i + 1000` in the benchmark's own loop building the literal
`1000` as an `Integer` every iteration, since folded
(`cast-fold-scope.md`, 54 ms and 35 allocations).

## Open questions

- **`apply` tails.** 790 functions end in a closure call, often a
  continuation. Nothing is known about what a closure returns, so these
  stay boxed.
- **Dynamic benefit.** The static counts and the model bound the gain.
  How often these chains actually run in idris2-lsp is unmeasured.
