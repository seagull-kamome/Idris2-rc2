# フィールドが読まれない結果 (`Compiler.RC2.DeadFields`)

(原文: `doc/dead-fields.md`。内容が乖離した場合は原文を正とする。)

呼び出し元が結果をすぐに分解する呼び出し`case f args of C x y => ...`では、一部のフィールドが読まれないことがある。`case isLTE k j of Yes _ => a; No _ => b`は証明も反駁も読まず、`case stats xs of (s, _) => s`はペアの片方だけを読む。それでも`f`はそれらをすべて作る。上流の`isLTE`のような再帰では、各ステップでそれらを作り、再帰呼び出しの後で結果を組み立て直さなければならないので、末尾呼び出しにならない。

このパスは、インライン化の後の名前付きのcase tree上で(プログラム全体のコンパイルでのみ)走り、そのような呼び出しに、その`case`が読まないフィールドを作らない`f`のコピーを与える。

- `case`がコンストラクタ`C`のフィールド`i`を読むとは、`C`の分岐があり、その本体がそのフィールドの束縛変数に言及していることをいう。分岐のないコンストラクタはデフォルトの分岐へ行き、デフォルトの分岐はそのフィールドを1つも読まない。
- コピーは`f`の本体であり、それが(`let`と`case`の分岐を通して)返すすべてのコンストラクタの、それらのフィールドを消去したものである。自分自身への末尾呼び出しは、コピーへの呼び出しになる。
- コピーの内部でも同じ書き換えを行う。そのため`case f k j of No c => No (g c); Yes p => Yes (h p)`(`f`自身の呼び出しを同じように分解するもの)もコピーを呼ぶ。その分岐は、分解したものを組み立て直すだけになる(`No _ => No _`)ので、`case`はそのスクルーティニーそのものになり、呼び出しは末尾呼び出しになる。上流の`isLTE`は、戻るまで何も確保しないループになる。
- コピーを残すのは、そのコードに見合う場合だけである。関数が30ノード以下であるか、300ノード以下でコピーがループである(自分自身への呼び出しがすべて末尾呼び出しで、分解して組み立て直すものが1つもない)場合である。見合わないコピーは、それを作る途中で作ったすべてのコピーとともに捨てる。それらのどれかが、そのコピーを呼ぶ可能性があるからである。
- コピーは、関数と読まれるフィールドの集合の組ごとに1つ(分岐の順序は問わない)、プログラム全体で最大500個である。対象は、パラメータを1つ以上持つ関数だけである。CAFは決してコピーしないので、そのメモ化された値は1つのままであり、コピーはそれを共有する。

## 決して省かれないもの

フィールドを消去するのは、それを計算しても値を作る以外に何も起こりえない場合だけである。つまり、ローカル、定数、プログラムの関数(パラメータを1つ以上持つもの。CAFを名指すと最初の評価が起きるので、CAFへの参照や、プログラムが定義していない名前への参照は残す)、それらのコンストラクタや算術、ラムダや遅延値(作るだけで実行はしない)、それらの`let`や`case`である。呼び出し(worldトークンや`unsafePerformIO`を通してIOを行う可能性がある)、worldのプリミティブ、`force`(中断された計算を実行する)、`crash`、除算(失敗する可能性がある)は対象外である。フィールドを消去できない場合、コピーは作らない。

このパスが消去するのはフィールドの式であり、束縛は決して消去しない。IOアクションに束縛されたローカルであるフィールド(`let y = unsafePerformIO (...) in (x + 1, y)`)は消去されるが、アクション自体は実行される。

デフォルトでは無効である(`--directive deadfields`で有効になる)。以下で測定した2つのプログラムでは、測定できる変化がなかった。

`Test183DeadFields`: プログラム内の`Dec`の再帰(名前を変えた上流の`isLTE`)は、証明を作らずに自分自身を呼ぶコピーを得る。片方だけが読まれるペアは、個数を数えないコピーを得る。IOアクションが作るフィールドは消去され、アクションは引き続き出力する。このテストはパスを有効にする(`%cg rc2 deadfields`)。出力はパスなしの場合と同じである。代わりに`myLTE 3000000 3000001`を使うと、パスなしでビルドしたプログラムはスタックオーバーフローを起こす(それぞれが`Yes`を組み立て直す300万個のフレーム)。パスありでは8 msで戻る。

## 測定結果

| | 命令数 | コード(`.text`) |
|---|---|---|
| コンパイラ自身による`prelude`のビルド、無効(デフォルト) | 27.971 G | 14.19 MB |
| サイズの上限なし(すべてのコピーを残す) | 27.990 G | 14.91 MB (+5.0%) |
| 上限あり(`deadfields`) | 27.972 G | 14.19 MB(同じ実行ファイル) |
| lambda-rogueのテスト、無効(デフォルト) | 21.014 G | 4.11 MB |
| サイズの上限あり(`deadfields`) | 21.012 G | 4.14 MB (+0.7%) |

上限なしでは、コンパイラの関数のコピーが45個作られ、そのうち6個(大きな関数全体)がコードの大半を占めた。命令数はわずかに増えた。上限ありでは小さなコピーが26個作られ、その後のインライン化と`FunDedup`によって同じ実行ファイルに戻る。どちらのプログラムにも、この形の深い再帰はない。このパスが対象とするのは上の`myLTE`のような再帰であり、スタックオーバーフローをループに変える。
