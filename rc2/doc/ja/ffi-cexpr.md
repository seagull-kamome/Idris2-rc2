# `CExpr:`: C式を`%foreign`のターゲットにする

(原文: `doc/ffi-cexpr.md`。内容が乖離した場合は原文を正とする。)

`"CExpr:<expression>,<lib>,<header>"`は、宣言を関数名ではなくC式または定数に結び付ける。マクロ、定数、1行の式のためにCのshim(薄い仲介関数)を書く必要がなくなる。

```idris
%foreign "CExpr:O_CREAT,libc,fcntl.h"
prim__oCreat : Int32

%foreign "CExpr:abs($1),libc,stdlib.h"
prim__abs : Int32 -> Int32

%foreign "CExpr:(($1) > ($2) ? ($1) : ($2))"
prim__max : Int -> Int -> Int

%foreign "CExpr:srand($1),libc,stdlib.h"
prim__srand : Bits32 -> PrimIO ()

%foreign "CExpr:mpz_add($r, $1, $2),libgmp,gmp.h"
prim__integerAdd : Integer -> Integer -> Integer
```

実装は`Compiler.RC2.ForeignSpec`(パースと検査)と`Compiler.RC2.Emit.Foreign`(`ffiRawCall`、`emitGenericForeignWrapper`)にある。テストは`rc2/tests/Test118FFI/FFICExpr.idr`、その`check.sh`と`CExprErrors/`、および`rc2/tests/Test119FFINoRefc/CExprPriority.idr`である。

## オプション

`CExpr:`より後ろの文字列は、最上位のカンマで分割する。1番目のオプションは式のテンプレートである。2番目はライブラリ、3番目はヘッダファイルで、`"C:"`とまったく同じに扱う。ヘッダは`#include`され、ライブラリはリンクされる(`libfoo`は`-lfoo`になる)。ライブラリとヘッダはどちらも省略できる。

ヘッダの欄には、`;`で区切って複数のヘッダを書ける。たとえば`"CExpr:O_CREAT|S_IRUSR,libc,fcntl.h;sys/stat.h"`である。各名前の前後の空白は取り除き、空の要素(末尾の`;`など)は無視する。異なる名前はそれぞれ`#include <...>`の1行になる。名前は文字列として厳密に比較する。大文字と小文字は区別し、パスの正規化もしないので、`a.h`と`./a.h`は別の名前である。したがって、同じ欄の中で繰り返されたヘッダも、複数の宣言から(単独でもリストの一部でも、どのタグの下でも)指されたヘッダも、1回だけインクルードされる。空白、`<`、`>`、`"`を含む名前はコンパイルエラーになる。`;`が特別な意味を持つのはこの欄だけである。式の中では普通のCのテキスト(`({ a; b; })`)であり、ライブラリの欄では何も変わらない。オプションを区切るのは、最上位のカンマだけである。

互換性について。上流とRefCは、ヘッダの欄を1つの名前として読む。そのため、RefCでもコンパイルできなければならない宣言は、`"C:"`の選択肢に単一のヘッダだけを残す。複数ヘッダの形は、RefCが無視する`CExpr:`か`RC2:`で書く。

インクルードの順序について。インクルードは、ヘッダ名のアルファベット順に出力する(最初に現れた順ではない)。出力位置は`idris2rc2_runtime.h`の後である。したがって、ヘッダは自己完結にしておく。別のヘッダを先にインクルードしておく必要があるヘッダは、自分でそれをインクルードしなければならない。

分割するとき、`()`、`[]`、`{}`の入れ子と、Cの文字列リテラルおよび文字リテラル(バックスラッシュのエスケープを含む)を考慮する。そのため、マクロ呼び出し、文字列リテラル、文字リテラルの中にあるカンマでは分割されない。各オプションの前後の空白は取り除く。括弧が閉じていない場合と、リテラルが終わっていない場合は、コンパイルエラーになる。この分割は、rc2が受け付けるすべてのタグ(`CExpr:`、`RC2:`、`RefC:`、`C:`)に適用され、上流のカンマだけで区切る`parseCC`を置き換える。`C:`、`RefC:`、`RC2:`の文字列は、以前と同じようにパースされる(既存のものに括弧や引用符を含むものはない)。検査の対象になるのは、宣言で選ばれた文字列だけである。最初の`:`より後ろにある`:`(`?:`など)は、式の一部である。

## プレースホルダ

| 表記 | 意味 |
|---|---|
| `$1`, `$2`, ... `$10` | 宣言の引数。1始まりで、桁数に制限はない |
| `$r` | `Integer`の結果の出力引数(`mpz_t`)。「Integerの結果と引数」を参照 |
| `$$` | 文字としての`$` |

`IO`/`PrimIO`型の末尾にある`%World`は、引数ではなく、数に入れない。使わない引数があってもよい。同じ`$N`を複数回書いてもよく、その場合は、引数をマーシャルした式がそのまま繰り返される。引数は読み出しか純粋な計算なので、副作用のために評価されるわけではない。`$0`、引数の個数を超える`$N`、直後が数字・`r`・`$`のどれでもない`$`は、宣言の名前を示すコンパイルエラーになる。(`$r`は最長一致で読む。`$result`は、`$r`の後に`esult`が続くものとして扱う。)

プレースホルダはテキストとして置換する。テンプレート内の文字列リテラルの中にあるものも置換される。

## 括弧付け

各プレースホルダは、マーシャル済みの引数の式を括弧で包んだものに置換される。たとえば`$1`は`(v123)`や`((idris2rc2_to_i32(v123)))`になる。このため、引数が、置換先の式の優先順位を変えることはない。式全体は、値として使うときは括弧で包んで出力する。`PrimIO ()`の宣言では、裸の文(`expr;`)として出力する。

宣言の式全体は、外側を1組の括弧で包むことを勧める(`CExpr:((int)send(...))`、`CExpr:(EPOLLIN)`)。隣のオプションの書き間違いが、分かりにくいCの構文エラーに化けるのを防げる。

## 結果と型

引数はIdrisの型に従ってマーシャルし、結果は`"C:"`の呼び出しの結果とまったく同じように詰める(dual-ABIのworkerではネイティブのまま保つ)。`Int32`は狭められ、`String`は`const char *`になり、`Ptr`型は`void *`、`Char`は`char`になる。`CFBuffer`の引数は、`"C:"`と同様に、平らなデータポインタへ取り出される。

式は、Idrisの型が対応するCの型の値を生成しなければならない(`PrimIO ()`ではどんな式でもよい)。

`CExpr:`の宣言にプロトタイプは出力しない。マクロや関数を見えるようにする手段は、ヘッダオプションだけである。

## Integerの結果と引数

`Integer`の結果は、Cの戻り値ではなく、GMPの出力引数である。`"C:"`は、この出力引数を関数の引数リストの先頭に付け足す。`CExpr:`には付け足す先の呼び出しがないので、テンプレートの中で`$r`によって位置を指定する。`$r`は、結果の型が`Integer`か`PrimIO Integer`のときだけ使える。

```idris
%foreign "CExpr:mpz_add($r, $1, $2),libgmp,gmp.h"
prim__add : Integer -> Integer -> Integer

%foreign "CExpr:mpz_set_si($r, (long)($1)),libgmp,gmp.h"
prim__fromInt : Int -> Integer

%foreign "CExpr:mpz_pow_ui($r, $1, (unsigned long)($2)),libgmp,gmp.h"
prim__pow : Integer -> Int -> Integer
```

rc2はまず新しい`IDRIS2RC2_Integer`を確保し、各`$r`をその`mpz_t`メンバ(`retVar->v`)に置換する。続いて式を裸の文として出力する(値があっても捨てる)。最後に、確保したIntegerを返す。収まるときは即値に正規化する点も、`"C:"`と同じである。`$r`は、テンプレートのどこに何回書いてもよい(たとえば`(mpz_set_si($r, 3), mpz_mul($r, $1, $r))`)。`$N`と違って、括弧では*包まない*。`retVar->v`は後置式なので、周囲の文脈によって意味が変わることがない。また、`sizeof`に渡す場合や、呼び出しで`mpz_ptr`に退化する場合のために、配列のままにしておく必要がある。出力引数はこの1つだけである。2つ持つ関数(`mpz_tdiv_qr`)にはshimが要る。

`Integer`の引数`$N`は、`"C:"`と同様に、その引数の`mpz_t`(即値を含めて`mpz_ptr`)になる。どのプレースホルダとも同じく、括弧で包まれる。呼ばれる側は、読むだけにしなければならない。

結果が`Integer`なのに`$r`がない場合は、コンパイルエラーになる。結果が`Integer`でない宣言に`$r`がある場合も、コンパイルエラーになる。値を返すGMP関数(`mpz_get_si`、`mpz_sgn`、`mpz_cmp`)は、対応する結果の型で宣言し、`Integer`の引数を取らせる。`Integer`を作りたいときは、Idris側でラップする。

```idris
%foreign "CExpr:mpz_sgn($1),libgmp,gmp.h"
prim__sgn : Integer -> Int
```

rc2が、このような値を`Integer`に自動で変換することはない。

## 制限

- 他のバックエンドは`CExpr:`を無視する。他のバックエンドでもビルドできなければならない宣言には、そのバックエンド自身のタグも併記する。

  ```idris
  %foreign "CExpr:abs($1),libc,stdlib.h"
           "C:abs,libc,stdlib.h"
           "scheme:abs"
  ```

## 優先順位

`CExpr:`は、宣言内の文字列の順序にかかわらず、`RC2:`、`RefC:`、`C:`より先に探される。
