# 本体が等しい関数の統合: `Compiler.RC2.FunDedup`

(原文: `doc/fun-dedup.md`。内容が乖離した場合は原文を正とする。)

クローンの作成とリフトのあとには、ローカル変数の番号付けを除けば本体が同じ関数が、数多く残る。同一のラムダからリフトされたクロージャ、結果が等しくなった特殊化クローン、等しいwrapperに対するDualABIのworkerなどである。idris2-lspの最終的なIR(定義17,370個)では、5,157個の定義(30%、IR行数の4.3%)に双子があった。大半は3行のスタブで、本体が6行を超えるグループは239個あった。

`dedupFuns`は、`toRCDefs`のプログラム全体を対象にする最後のステップである。最後のDup/dropの相殺のあとで、プログラムを出力する前に走る。`--directive nofundedup`で無効にできる。インクリメンタルモードでは走らない。このモードでは、各モジュールが自分の定義しか見られないためである。

## 手順

1. **候補。** 引数を1つ以上持つ`MkRCFun`である。CAF(`RMemoize`)は対象外とする。インライン化されたFFI呼び出しや、フィールドを持つ定数コンストラクタ(`hasFatConst`)を含む関数も対象外とする。前者は構造的に比較しないためで、後者は巨大な木に展開されうるためである。
2. **浅いキー。** 次をまとめたものである。
   - 引数の数
   - ノード数
   - 引数と返り値の表現、およびworkerフラグ
   - 本体が参照する関数の集合。関数自身の名前はプレースホルダに置き換え、自己再帰する双子どうしが一致するようにする。
   - 定数とコンストラクタの、走査順のハッシュ(`leafHash`)。定数だけが違うスタブが同じバケットに入らないようにする。

   同じキーを持つ関数どうしだけを、さらに比較する。先頭10ノードの先行順ハッシュも試した。idris2-lspでは結果が同じで、時間が少し増えたため、採用していない。
3. **構造の比較**(`sameFun`/`eqE`)。2つの本体を並行して走査する。片方のローカル変数は、束縛されるたびにもう片方のものと対応付ける。束縛するのは、引数、`let`、caseの代替、ループの引数である。この対応は1対1のままでなければならず、ローカル変数の使用は、その対応先に当たらなければならない。関数自身の呼び出しは、もう一方の関数自身の呼び出しと一致する。最初の違いで比較を打ち切り、途中で何も構築しない。比較が扱わないコンストラクタ(構造体アクセス、インライン化されたFFI呼び出し、メモ化)は、何とも等しくならない。
4. プログラム順に、ルート(`main`とエクスポート)を先頭にして、各関数を、同じバケットでこれまでに見つかった互いに異なる関数と比較する。等しいものがあれば、その関数をそちらにリダイレクトする(`renameNamesR`を、すべての呼び出し、部分適用、`delay`、クロージャ定数に適用する)。ルートがリダイレクトされることはない。
5. 統合の結果、呼び出し元どうしが等しくなることがある。そのため、この手順を最大4回繰り返す。リダイレクトされた関数は、以降の回の比較からは外れるが、リストには残る。
6. `pruneDeadDefs`が、どこからも参照されなくなったものを取り除く。

以前の版は、`dumprcexpr`のテキストでローカル変数の番号を振り直したものをキーにしていた。この方法はうまくいかない。`libs/rc2base/tests/TestWebAPI`では、インライン化されたFFI呼び出しを持つ関数を`Pretty`が最後まで出力できなかった(`dumprcexpr`がこのテストでメモリ不足になるのと同じ理由である)。また、候補ごとにテキストを作るコストは、2つの木を比較するコストよりはるかに大きい。

`RCConstCon`のフィールドの名前は置き換えない。消去された証明は再構築できないためである。そのため、そこでしか名前が出てこない関数は残る。安全ではあるが、統合は徹底されない。Test114Inline/FunDedupは、この問題を痛い目に遭って見つけた。統合した関数をすぐに捨てると、`constclosure`が宙ぶらりんになったのである。

## 結果

idris2-lspでは、定義が17,370個から12,705個になった(-27%)。`rcexpr-lint`は問題を報告しない。パスの所要時間は約1.7秒である。`libs/rc2base/tests`は34個すべて通る。

## テスト

`Test114Inline/FunDedup`である。`check.sh`は、等しい2つのループのうち1つだけが残ること、別の定数を持つループは自分自身を保つことを確かめる。`--directive nofundedup`を付けると、このテストは失敗する。
