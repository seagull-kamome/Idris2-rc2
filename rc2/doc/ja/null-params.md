# NULLを保持するパラメータ: worldとerasedな値

(原文: `doc/null-params.md`。内容が乖離した場合は原文を正とする。)

worldトークンとerasedな値は、常にCの`NULL`である(`doc/world-erased-marks.md`)。`Compiler.RC2.NullParams`は、そのどちらかしか保持しえないパラメータを見つける。`DualABI`は、そのような各パラメータにネイティブな型を与えるので、ワーカーはそれに対して参照カウントの操作をしない。

## 型

`NativeTy`には`TPrim WorldType`(world)と`TErased`がある。どちらも値を持たないので、`Types.tyAlwaysUnboxed`は真になり、`Types.nullTy`がこれらを選び出す。Cの型は不透明な構造体へのポインタ`IDRIS2RC2_World *`と`IDRIS2RC2_Erased *`である(`support/rc2/idris2rc2_datatypes.h`)。そのため、Cコンパイラはこの2つを互いに区別し、`IDRIS2RC2_Value *`とも区別する。

- ボックス化(`tyMk`)すると`NULL`の`IDRIS2RC2_Value *`になる。アンボックス化(`tyUnbox`)すると、Boxedの値が何であれ、型付きの`NULL`になる。
- `nullOfTy`は、ネイティブな型が求められる場所で定数`[__]`、`[erased]`、`[world]`を読んだときの値である。
- ダンプでは`Native %World`と`Native Erased`と表示する。`rcexpr-lint`は、どちらも常にアンボックスな型として数える(`Leak.unboxedTypeNames`)。

## 型の出どころ

`NullParams.nullParamTable roots defs`は、関数ごとに、NULL型のパラメータのidを返す。出どころは2つある。

1. **型から、後ろ向きに。** `%foreign`宣言の`CFWorld`スロットはworldである。`call`(`RAppName`)や部分適用(`RUnderApp`)でそのようなスロットに渡されるパラメータもworldである。名前付きの呼び出し先をたどって、新しく見つかるものがなくなるまでこれを続ける。変数の型は1つなので、これはエスケープする関数(クロージャやエクスポート)についても成り立つ。
2. **値から、前向きに。** 関数が *closed* であるとは、その関数へのすべての参照が、呼び出しか、引数リストの分かっている`RUnderApp`であることをいう(定数クロージャ、`RDelay`、dual-ABIのワーカー呼び出し、ルートはいずれも該当しない)。そのような関数では、すべての呼び出しが位置`i`に`[world]`か`[erased]`、または呼び出し元の、それ自体NULL型のパラメータを渡すとき、パラメータ`i`はNULL型である。`RUnderApp`は`i`を覆っていなければならない(そのプレフィックスより後ろの引数は、このパスから見えない呼び出し元から来る)。解析は「すべてのパラメータがNULL型である」から始め、どこかの呼び出し箇所と矛盾するものを取り除いていく。そのため、再帰の中で受け渡されるだけのパラメータは報告されないまま残る。すべてworldなら`TPrim WorldType`、そうでなければ`TErased`になる(どちらもNULLである)。

`MutualLoop`がまとめた関数は対象外である。`--directive nonullparams`で解析を無効にできる。

## `DualABI`での扱い

`applyDualABI`は、NULL型のパラメータを関数の`eligible`リストに加える。そのため関数は、ほかのネイティブなパラメータと同じように、ワーカー(ネイティブなパラメータを取る)と、Boxedのシグネチャを保つ薄いラッパを持つ。

- ワーカーでは、そのパラメータに対する`dup`/`drop`/`free`/`postDrop`を取り除く(`stripOwnership`)。`RExtPrim`の`postDrop`も取り除く。パラメータ(とその別名)の読み取りはすべて定数`[world]`または`[erased]`になる(`nullReads`)。そのため、後段のパスには定数が見える。
- NULL型のローカル変数の名前を付け替えるだけの`let`もNULLである。そのため、同じ型のネイティブなローカル変数になり、所有権の操作を失う(`nullAliasTypes`、`nativeAliasLets`)。
- 関数のパラメータと同じidのパラメータを持つ`RLoop`は、同じネイティブな型を取る(`retypeNullLoopParams`)。そのidのC変数がすでにその型を持つ場合(パラメータ自身、または別名の`let`)、`Emit.declareLoopParam`はそれについて何も宣言しない。ループの開始時に読むのは、もう変数そのものではなく定数だからである。
- ラッパはそのような引数をdropしない。NULLだからである。
- 呼び出し元は、通常の呼び出し箇所の書き換えによって、ワーカーを呼ぶように書き換わる。

パラメータはシグネチャに残る。アリティも、worldの位置も、副作用の順序も変わらないので、`ArityRaise`と`IO`の評価には影響しない。そこでは引き続き`worldInPrefix`がガードになる。「worldである」という印は「worldではない」ことを証明しないからである(`doc/world-erased-marks.md`)。

## 測定

定数への書き換えを入れる前、スモークテストの56個のIRダンプで、印が付いたパラメータは190個(world 169個、erased 21個)だった。`dup`は2111から2058に、`drop`は3795から3782になった。

idris2-lsp(`9a2f0ad`、定義13.2k個)で、この変更の前のビルド(#119をマージした時点のmaster)と比べた結果:

| | 変更前 | 変更後 |
| --- | --- | --- |
| `dup` | 73320 | 69886 (-4.7%) |
| `drop` | 62606 | 61594 (-1.6%) |
| 合計 | 135926 | 131480 (-3.3%) |
| ワーカー | 1687 | 2031 |
| IRの行数 | 629736 | 628232 |

印が付いたパラメータは667個(world 639個、erased 28個)である。344個の関数は、このためだけにワーカーを得る。それでもIRは小さくなる。それらが省く`dup`/`drop`の行数が、ワーカーが増やす行数を上回るからである。`rcexpr-lint`は、どちらのダンプにも異常を検出しない。コンパイル時間は測っていない。

## スロットを共有するループ

`MutualLoop`は、相互再帰する関数の状態を1つのループにまとめる。そのループのスロットは、状態ごとに異なる意味を持つ。また`LateInline`は、そのようなループを任意の関数の中に置きうる。したがって、NULL型のパラメータ(またはその別名)を保持するループのスロットをNULL型のまま保つのは、ループの開始とすべての`continue`がそのスロットに、NULL型のローカル変数か`[__]`、`[erased]`、`[world]`を与える場合だけである(`DualABI.mixedSlots`)。それ以外のスロットがあれば、パラメータは`Boxed`のまま残る。この検査がないと、idris2-lspでは6個のループが、worldとして型付けされたスロットにオブジェクトを渡していた。


## コンパイル時間

idris2-lspでは、ビルド全体が56sから58sになる(それぞれ2回実行。`--directive nonullparams`と既定の比較)。`DualABI`は2.6sから2.8sになる。解析は、各名前に一度だけ振った番号を不動点のキーにしている(初版のコストの大部分は`Name`の比較だった)。見つけるまでに数分を要した落とし穴が2つある。

- `let x : T`と別の`x = e`を書くと(引数なしの`where`定義も同様)、`x`は *関数* になり、使うたびに`e`を評価し直す。値は`let x : T := e`で束縛する。初版は、前向きの不動点全体を関数ごとに1回ずつ実行していた。
- リストのリストに対する`concatMap`は、`++`を左にネストさせ、要素ごとに蓄積したリストをコピーする(`foldr (\g, acc => ... ++ acc) []`ならそうならない)。

## 未対応のこと

- `Loop`はこれらの型を見ない。関数自身のパラメータ(またはその別名)ではなく、そこから初期化されるループのパラメータは、Boxedのまま残る。
- 受け渡されるだけのパラメータ(`%foreign`のworldスロットに渡されることも、すべての呼び出し元から定数として渡されることもない)は、Boxedのまま残る。
