# termui の設計

*[English](../design.md)*

`termui` は、JavaScriptの Ink に着想を得た、Idris2向けのリッチなターミナルUIライブラリです。レイアウトEDSLでビューを記述すると、レイアウトエンジンが画面を計算し、前回の画面からの差分のみを端末に書き出します。tmux配下で不具合を起こしやすい notcurses は使用せず、カーソル移動や画面消去には `contrib` パッケージの `Control.ANSI.CSI` を用いたプレーンなANSIエスケープシーケンスで出力します。

## パイプライン

```
Msg ──► update : Msg -> Model -> (Model, Cmd Msg)        TermUI.Program
                         │
                  view : Model -> Node Msg                TermUI.Node
                         │
                  layout                                  TermUI.Layout   純粋計算
                         │
                  paint into a Frame                      TermUI.Frame
                         │
                  diff against the previous Frame         TermUI.Output
                         ▼
                  1つの文字列、1回の write(2)
```

差分計算の手前までの処理はすべて、実際の端末から完全に独立しています。フレームはテキストとしてダンプでき（`frameLines`）、テストではこの機能を使って描画結果を検証しています。

## レイアウトのセマンティクス

CSS flexbox のサブセットです。寸法はセル単位で扱います。

画面上のサイズ、座標、オフセットは `Nat` ではなく `Len`（`TermUI.Len`、`Int32` の別名）です。端末の画面幅が 2^31 セルに達することは到底なく、また rc2 が生成するコードにおいて `Nat` がヒープ確保を伴う `Integer` であるのに対し、`Int32` はネイティブな `int32_t` として扱えるためです。`Len` は負の値も取ることができます。`monus` は 0 未満にならない飽和減算であり、サイズが負になってはならないレイアウト計算で用いられます。各種プロパティ構築関数（`width`, `padding`, `gap`, `top` など）や `newFrame`, `getCell` は負のサイズを 0、負の位置を枠外として扱います。項目数やインデックス（タブの番号や行番号など）は `Nat` のままですが、リスト系ウィジェット（`Select`, `Scroll`, `Table`）は表示ウィンドウと選択位置を `Len` で保持します。`TextArea` は内部で `Nat` を数え、外部との境界で `Len` を受け取ります。

- 箱（box）の `width`/`height` は、ボーダーボックス（枠とパディングを含む）の寸法です。マージンはその外側に位置します。`Auto`、`Cells n`、`Percent p`（親の内部寸法に対する割合）が使用できます。
- ルートノードは画面全体を満たします。ルートノード自身の `width`/`height` は無視されます。
- `direction` は主軸を指定します（Ink と同様、既定値は `Column` です）。子要素は主軸上でそれぞれの自然なサイズ（natural size）を取り、残余スペースは `grow` で分配されるか、不足分は `shrink` で削られます（基本サイズで重み付けされます）。端数は先頭側の子要素に配分されるため、結果は決定的です。
- `justify` は主軸上の（残余）スペースの配分を決定し、`align` は交差軸上の子要素の配置を決定します。`Stretch`（既定値）は、サイズが `Auto` である子要素の交差軸サイズを親の幅/高さ一杯に引き伸ばします。
- テキストの折り返しは、単語境界（`WrapWords`）、任意文字（`WrapChars`）、切り詰め（`Truncate`）から選択できます。行幅より長い単語は途中で分割され、末尾の改行文字が余分な空行を作ることはありません。テキストは自身の箱でクリップされ、子要素は親のコンテンツボックス（枠とパディングの内側）でクリップされます。
- 空白のない文字の連続の途中で改行する場合、日本語禁則処理（`TermUI.Kinsoku`）が適用されます。閉じ括弧、句読点、小書き仮名、長音符は行頭に来ず、開き括弧は行末に来ません。改行直前の文字は最大3文字まで次の行に送られます。それでも解消しない場合はそのまま改行されます。この禁則処理は `Text`、スタイル付きテキスト、エディタのすべてで共通して働きます。
- ノードの自然なサイズは、与えられた利用可能幅に対して計算されます。そのため折り返されたテキストは、幅が決まった後で必要な高さを取ります。子要素の幅は、まず制約がない場合に各子が要求する幅（`maxContent`: テキストを折り返さない幅。部分木のサイズに対して線形）から決定され、分配されます（行は `grow`/`shrink`、列は交差軸配置による）。その後、各子は決定した幅で1度だけ測定されます。したがって折り返されたテキストは最長行の幅ではなく与えられた幅を取ります（CSSの `fit-content` と同様）。そのため `align Center` や `JEnd` によってテキストが幅の狭いブロックに縮むことはありません（縮めたい場合は箱に明示的に幅を与えます）。最悪計算量は「木のサイズ × 深さの2乗」です（深さ640のチェインでも1秒未満で計算されます。以前は階層ごとに倍増していました）。
- `minWidth`/`maxWidth`/`minHeight`/`maxHeight` はボーダーボックスを制限します（最小値が最大値に優先します）。これらは子の基本サイズに適用されます。分配後に制限によってサイズが変わった子は制限値に固定され、余った、あるいは不足したスペースは他の子要素で再分配されます（どの制限も違反しなくなるまで分配が反復されます）。
- 行（`row`）における `wrapChildren`: 次の子要素が幅に収まらない場合、新しい行に折り返されます（CSSの `flex-wrap` と同様）。行間は `gap` だけ離れ、各行は独自に分配・均等配置され、交差軸（`align`）はその行ごとのものとなります。行の幅より広い子は独立した1行を取ります。列（`column`）の折り返しも同様で、配置された高さの中で行われます。子は右側の新しい列へと進み、列間は `gap` 離れ、各列は最も広い子の幅になります（`align` はその列内で子を配置します）。折り返す列の自然なサイズには自身の高さが必要です。`maxContent`（親が幅を決める値）は最も広い子のみを数えるため、他の要素と並ぶ場合は折り返し列に幅を指定してください。
- `absolute`: 箱を通常のフローから除外します。スペースを取らず、兄弟要素を動かしません。`top`/`right`/`bottom`/`left` で親のコンテンツボックス内に配置されます（対向する2辺を指定すると `Auto` サイズが引き伸ばされます。指定しない辺はフリーとなり、何も指定しない場合は開始位置に置かれます）。マージンは指定された辺からのオフセットとなります。通常のフローの後に描画されるため、重なる要素の上に重なります。子を中央揃えするオーバーレイは `box [absolute, top 0, left 0, right 0, bottom 0, align Center, justify JCenter] [child]` と書けます。
- 縮小する要素のサイズが 0 未満になることはありません。吸収しきれない不足分は他の要素に再配分されます。`JAround` は除算の端数を切り捨て、`JBetween` は最初の隙間に端数を配分します。
- `marginPercent`/`marginPercentXY`: 親のコンテンツ幅に対するパーセンテージでマージンを指定します（CSSと同様に全辺に適用）。セル単位のマージンに加算されます。親のサイズ決定（`maxContent`）では計算に含まれません。
- 未実装: 行の高さが決まる前の、行の子要素に対する高さの `Percent`。
- `Style` は前景色、背景色、有効な属性、無効な属性からなります。親のスタイルに重ねて適用（`over`）されます。`Inherit`（既定値）は親の色、`Default` は端末自身の前景色/背景色です。`withAttr`/`withoutAttr` でオン/オフされた属性が優先され、それ以外は親の属性を引き継ぎます。したがって子は親の太字をオフにしたり端末の色に戻したりできます。ルートでまだ `Inherit` のままのものは端末自身の色に解決され（`settle`）、それがセルに格納されるスタイルとなります。

## 文字と文字幅

文字幅は `wcwidth(3)` に従います。制御文字や結合文字は 0 セル、東アジアの全角文字や絵文字は 2 セル、その他は 1 セルです。全角文字は 1 セルに加え、同じスタイルを持つ継続セル（`'\0'`）を占有します。

結合文字（アクセント記号など、`isMark`）はその直前の文字のセルに保持され、端末がその位置に描画します。同じ `Text` 内に直前の文字が存在する必要があります（テキストの先頭にある結合文字は結合先がないため破棄されます）。その他の幅 0 文字は描画時に破棄されます。絵文字の ZWJ シーケンスや異体字セレクタは合成されません（端末がその前後を合成したり広げたりする可能性があり、セルグリッドがそれに追従できないためです）。箱の右端に収まらない全角文字はスペースに置き換えられます。

## フレームのメモリ配置

`Frame` は行優先（row-major）順に並んだ 16 バイトのセルの単一 `Buffer` です。描画と差分計算（diff）はワードの読み書きで行われ、セルごとのメモリ確保は一切発生しません（`Cell` レコードと `Style`, `Color` を持たせると 1 セルあたり複数のヒープオブジェクトが必要になり、空白セルも共有オブジェクトへの参照カウント更新が書き込みごとに発生してしまうためです）。

1 セルは 4 つの `Bits32` ワード（計 16 バイト）で構成されます。

| オフセット | ワード |
|---|---|
| 0 | グリフ: コードポイント xor `' '` |
| 4 | 前景色 |
| 8 | 背景色 |
| 12 | 属性（bit 0-7）。セルに結合文字がある場合は bit 8 がセットされる |

- 色は最上位バイトにその種別を保持します。`Default`（およびセルには保持されない `Inherit`）は 0、`Indexed n` は `0x01000000 + n`、`RGB r g b` は `0x02000000` に続く 3 バイトです。
- グリフ xor `' '` と `Default = 0` という設計により、すべて 0 のセルは「空白・デフォルト色のセル」になります。そのためゼロ初期化されたバッファ（`newBuffer` はゼロ埋めを行います）はそのまま空白フレームとなり、`newFrame` は初期化書き込みを一切行う必要がありません。
- 結合文字は固定長のセルに収まりません。そのためセルのバイトオフセットから結合文字（最大8個）へのサイドマップに保持され、bit 8 のフラグによってマップを参照すべきかどうかが分かります。結合文字のない同一フレームは、セルあたり 2 つの 64 ビットワード（128 ビット）として高速に比較されます。
- `getCell` はテストや差分書き出しなど、レコードが必要な呼び出し元のためにワードから `Cell` を構築します。ペインターや差分エンジン自体はこれを行いません。

## キャンバス

`Canvas` は、コンソールゲームやグラフ描画など、単一セルを直接描画するプログラムのためのセルグリッドです（フレームと同じメモリレイアウトを持ちます）。`IO` 内で作成・描画され、ビューの更新をまたいで描画内容が保持されるため、プログラムは変化したセルのみを書き換えることができます。

```idris
c <- newCanvas 40 20
putString c 2 1 (fgColor green plain) "SCORE 120"
fillRect c 0 19 40 1 '=' plain
...
view = box [border Single] [canvas c]
```

`canvas c` はキャンバスのサイズのノードです（周囲の箱に `width` や `height` を指定することで切り抜いたり余白を空けたりできます）。フレームへの描画は行単位のセル一括コピーで行われ、セルごとの処理コストはかかりません。

- キャンバスには結合文字はありません。スタイルは絶対的です。`Inherit` は端末独自の色となり、周囲の箱の太字や色はセルには届きません。
- 全角文字は 2 セルを占有します。その半分の上に重ねて描画すると、もう半分は空白になります。キャンバスの端、周囲の箱、あるいは上書きによって切られた全角文字は、フレームと同様に空白になります。
- フレーム内のキャンバスの下層にあるもの（テキストや境界線など）は、キャンバスの領域全体にわたってセル・結合文字ともに完全に置き換えられます。
- キャンバスは可変（mutable）で共有されます。`mapNode` や同じ `canvas c` を2回構築するビューは、同じセルを表示します。
- 描画処理はビュー関数に束縛されません。コマンドやタイマー（`Every`）を契機に描画を行い、次のビュー描画でその結果が画面に反映されます。キャンバス自体は入力を受け取らないため、キー入力を処理するには `focusable` で包んでください。

## 幅に応じたノード (withWidth)

`withWidth (\w => node)` は、配置されるボーダーボックスの幅に基づいてノードを構築します。折り返されるスタイル付きテキスト、横幅いっぱいの区切り線、割合指定のバーなど、幅に依存する要素に用います。

- 親が幅を固定しない場合、ノードは `w` が 4096 のときの中身の幅を要求します（テキストが最長行の幅を要求するのと同様で、それ以上に広がることはありません）。行内で他の子要素と並ぶ場合、すべての子が収まるようにサイズに比例して縮小されます。サイズを維持したい兄弟要素には `shrink 0` を指定します。
- 高さは配置された幅に応じて決まります（折り返しテキストと同様です）。
- ノードの本体はレイアウト処理中に複数回構築されます（測定、幅決定、配置、およびそれを測定する各祖先要素ごと）。本体の構築処理は軽量に保ってください。
- 親要素が `withWidth` ノードのサイズ決定と配置を行うため、本体が箱であってもその `width`, `height`, 最小/最大サイズ, マージン, `grow`/`shrink`, `absolute` は無視されます。これらは `withWidth` を囲む外側の箱に指定してください。
- `withWidth` の中にフォーカス可能要素（focusable）を含めることはできません。フォーカス可能要素はレイアウト計算の前に検索されますが、その時点ではノードがまだ構築されていないため、非フォーカス状態として配置されキーも受け取れません。

## ラベル

ボタン、チェックボックス、タブ（`TabStrip`）、メニュータイトルとメニュー項目（`MenuBar`）、キーヒント（`KeyGuide`）のラベルは `Label`（`TermUI.Widget.Label`）です。これはそれぞれスタイルを持つスパン（`TermUI.Widget.Span`）の 1 行です。文字列リテラルはそのままラベルとして使用できます（`button Framed "Save" Save`, `T.fromTitles ["List", "Controls"]`, `Item "Open" Open` など）。`Label` が `FromString` の実装を持つためです。部分ごとにスタイルを変えたい場合は `styledLabel [spanOf bold "S", spanOf plain "ave"]` を使い、変数や式の `String` を渡す場合は `plainLabel s`（リスト用には `plainLabels`）を使用します。各ウィジェットが `Label` を再エクスポートしているため、利用側で直接参照できます。

- ウィジェットがラベルに与えるスタイル（フォーカス時の反転、リンクの下線、フラットボタンのグレー背景、メニュー項目のハイライトなど）は、各パーツのスタイルのベースとなります。パーツ自身が明示的に設定したスタイルが優先され、それ以外（`Inherit` のままの色、設定されていない属性）はウィジェット側から継承されます。したがってフォーカスされたボタンの赤い文字部分は、赤色のまま反転表示されます。
- ラベルは 1 行です。パーツ内の改行文字はラベル作成時に破棄されます。独自のスタイルを持たないラベルは文字列と同様に単一の `Text` として描画されるため、狭い箱の端では同じように切り詰められます。スタイル付きパーツを持つラベルはそれらの行（`row`）となります。幅（`labelWidth`）に基づいてタブやメニュータイトル、ヒントが配置され、全角文字を含めてクリックが正しい位置に届きます。
- `Select` の項目や `Table` のセルは文字列のままです。複数行にわたるテキストには `StyledText` を使用します。

## スタイル付きテキスト

`TermUI.Widget.StyledText` は、部分ごとに異なるスタイルを持つテキストを表示します（チャットログやゲームのメッセージ、後述のMarkdownビューアなど）。モデルは段落（paragraph）のリストです。段落はテキストのスパン、1行目のプレフィックスと2行目以降のプレフィックス（箇条書きの記号やインデント、引用バーなど）、および折り返し方法（`WrapWords`, `WrapChars`, `Truncate`）を持ちます。`styledText w t` は段落を `w` セルに折り返し、1行ごとに `Text` ノードの行を持つ列（column）を返します。`styledLines` はスクロールウィジェット用の行リストを返し、`layoutLines` はテスト用のスパンリストを返します。

- レイアウトには幅が必要ですが、ビューの側では幅があらかじめ分かりません。`styledView t` は `withWidth` ノードであり、配置された幅に合わせて自動で折り返されるため、ウィンドウのリサイズ時にも新しいビューを作る必要がありません。一方 `styledText w t` はプログラムが明示的に指定した幅に折り返します。
- 単語の分割は空白（U+0020 のみ）で行われます。空白で区切らない言語のテキストは1つの単語として扱われ、行より長い単語と同様に幅で分割されます。行末に来る空白や折り返し行頭に来る空白は破棄されますが、段落先頭の空白は収まる限り維持されます。プレフィックスのために2行目以降より狭くなっている1行目に収まらない単語でも、2行目以降に収まる場合は2行目に送られます。スパン内の `\n` は同じ段落内で新しい行を開始し、2行目以降用のプレフィックスが付与されます。
- 幅はセル単位で計算されるため（`TermUI.Width`）、全角文字は 2 セルを占有します。
- 幅に対して無効なテキスト（行幅と同じ幅を持つプレフィックスなど）には特別な処理は行われず、1文字ずつ折り返されます。
- 他の形式は `StyledText` に変換して読み込まれます。代表的なものが `TermUI.Widget.StyledText.Doc.fromDoc : (ann -> Style) -> Len -> Doc ann -> StyledText` であり、`contrib` の pretty-printer 用のドキュメントを変換します。ドキュメントは `layoutPretty` によって指定幅向けにレイアウトされるため、`group`, `nest`, `hang` はその幅のページのように適切に改行されます。アノテーションはスタイルに変換され、内側のスタイルが外側に優先されます。インデントされた行はさらに折り返されてもインデントが維持されます。空のドキュメントは段落なしとなり、最終改行後の空行は表示されません。

## Markdown

`TermUI.Markdown` は、テキストをブロック（`Heading`, `Paragraph`, `CodeBlock`, `Quote`, `Bullets`, `Numbered`, `Rule`。リスト項目はブロックのリスト）とインライン（テキスト, 強調, 強い強調, 打ち消し, コード, リンク, 強制改行）にパースします。汎用的なMarkdownライブラリではなく、チャットやヘルプテキストで使われるものに特化しています。テーブル（`|` で始まる行は改行を保持）、HTML、setext見出し、インデントによるコードブロック、参照リンクには対応していません。生の `http(s)://` アドレスや `<...>` 形式のアドレスはリンクになります。ソフト改行はスペースとして扱われます。

逐次テキストが追記される用途を想定して作られています。途中で途切れたテキストも可能な限り読み取られます。閉じられていないフェンスは残りを保持し、閉じられていない強調はプレーンテキストとして扱われ、入力途中のリストマーカーは直前の行の一部となります。テキストの最終行は、後続のテキストによって別の要素に変わり得ます（`#` や `---` は、後続に `#include` や `---Note` が続くと見出しや罫線ではなくなります）。その場合、直前のブロックも変化するため、後続テキストが追加された際に最後の2ブロックより前のブロックは完全に不変であることが保証されます（テストで各長さで切断して検証されています）。そのため追記時は最後の2ブロックのみを再パースすれば済みます。後述のビューアでは、最後のセグメント全体のテキストを毎回使用します（最後の2ブロックだけでなくセグメント全体が再パースされます）。

`MdTheme` は見た目をプレーンなレコードとして定義します（`defaultTheme` と `{ field := .. }` 構文でカスタマイズ可能）。段落、各レベルの見出し、強調、強い強調、打ち消し、コード、リンク（およびリンクテキスト後のアドレス）、コードブロック（背景色含む）、引用、マーカーのスタイルを指定できます。またマーカー文字そのもの（見出しの `#`、リストの深さごとのビュレット記号、番号、引用バー、罫線、ブロック間の空行）や、各ブロック種別（`Kind`。見出しはレベルごと）に対して `fold : Kind -> Fold`（`NoFold`, `Open`: 折りたたみ可能で初期状態は開く, `Closed`: 初期状態は折りたたまれている）を設定できます。マーカーは既定でどの端末でも同じ幅になる ASCII 文字（ビュレットは深さに応じて `-`, `+`, `*`、引用バーは `|`）です。入れ子になったインラインのスタイルは `over` で重ね合わされるため、見出し内の強調は見出しの色を保持します。

`box : Kind -> BoxStyle` は、CSSと同様に各ブロック種別にセル単位・各辺（`Edges`、`TermUI.Node` のもの）のマージンとパディングを与えます。外側から順に: マージン（空白）、パディング（`fill` で描画）、ブロック本体となります。引用バーやリストマーカーはブロックの一部であるため、パディングの内側に配置されます。既定ではマージン・パディングはありませんが、コードブロックのパディングはコード本体と同じ背景色で描画されます。以下の規則があります。

- 隣接する2つのブロック間の空行は、`gap`、1つ目のブロックの下マージン、2つ目のブロックの上マージンのうち最大の値になります（マージンの相殺）。テキストの最初のブロックの上マージンは有効ですが、最後のブロックの下マージンは描画されません。これは引用内やリスト項目内のブロックにも適用されますが、リスト項目自体の間には適用されません。
- 右側にマージンやパディングがある場合、ブロックは残されたスペースに合わせて折り返されます（段落はブロック生成時に各行1つとして折り返されます）。右パディングがある場合、その行はパディング位置まで `fill` で描画されます。
- ブロックの本体に1セルも残らないような過大なマージン・パディングは左右には適用されません。負のサイズは 0 として扱われます。
- 折りたたまれたブロックは、左マージンとパディングの背後にある 1 行として描画され、上下のパディング行は省かれます（したがって折りたたむと折りたたみマークがテキストの行に移動します）。
- `fill` はパディングのみを描画し、テキストは自身のスタイルを保ちます。折りたたみマークと折りたたみクリック判定はボックスの最初の行にあり、上パディングがある場合はパディング行の上に置かれます。
- サイズの上限は 65535 セルです。

`foldClick` は、折りたたみ可能なブロックを左クリックで開閉できる位置を指定します。`OnMark`（既定値。1行目のガターにあるマーク上）、`OnFirstRow`（1行目の任意の場所）、`OnBlock`（ブロックの全行、パディング、左マージンの列を含む。上下のマージン行は除く）から選べます。ブロックの1行目より下をクリックした場合、その1行目が表示されます（ブロックがそこに縮小します）。スクロールバー上のクリックで折りたたまれることはありません。マークを `""` にすることも可能です。幅を持つマークが1つもない場合、ガターは消去され、カーソルはブロックの1行目の反転表示で示されます。この場合の折りたたみ状態は折りたたまれたブロックの `" ..."`（コードブロックの場合は線）で示されます。マークがない状態での `OnMark` はクリック対象がありません。

`renderMarkdown theme w src` は幅 `w` 向けのスタイル付きテキストを生成し、`markdown theme src` は配置された幅に合わせて折り返されるビューを生成します。引用やリスト項目は段落のプレフィックスを用いて作成されるため、折り返された行でも引用バーやインデントが維持されます。コードブロックの各行は幅に合わせて空白で埋められ、背景色がブロック全体に広がるように文字単位で折り返されます。罫線は配置領域の幅いっぱいに広がります。制限事項として、リスト項目内のフェンスブロックの直後にインデントなしで続く行はリスト項目のテキストとみなされます。閉じられていない `[`, `*`, `_`, `~~` があるとリーダーは段落の末尾まで対応する閉じ記号を探すため、そうした開始記号が多数並ぶ非常に長い段落のパースには2次関数的な時間がかかります。

`TermUI.Widget.MarkdownView` は、スクロールバー付きウィンドウ内にMarkdownを表示します。テキストはセグメント（チャットの各メッセージやページなど）単位で保持され、それぞれ独立してパースされるため、応答が届いている間も `extendSegment` は最後のセグメントのみをパースしてレイアウトします（`addSegment` は次のセグメントを開始します）。ブロックはテーマの `fold` 設定に従って折りたたむことができます。折りたたみの単位となるのはセグメントのトップレベルにあるブロックです。見出しはそのセクション全体（同じレベルまたはより上位の見出し、あるいはセグメント末尾までのブロック群）を折りたたみます（そのため応答内の見出しが、メッセージ自体の見出しセクションを終了させてしまうことはありません。同一レベルの場合を除きます）。その他のブロックは最初の段落の中に折りたたまれます（コードブロックなら `[+] ``` sh  (2 lines)`、リストなら `[+] - first ...` など）。左側のガター（マークと同じ幅）には、各折りたたみ単位の最初の行に `[-]` または `[+]` が表示されます。何も折りたたまないテーマの場合はガターは表示されません。各単位の開閉状態はセグメント番号とブロック番号で保持されるため、テキストが再レイアウトされても状態が維持されます。初めて現れたブロックの初期状態（`Open` または `Closed`）はテーマから取得されます。カーソル（`NextUnit`, `PrevUnit`）で選択された単位は反転したマークで描画されます。`Toggle` で開閉を切り替え、`FoldAll` と `UnfoldAll` で一括開閉でき、ガター内の特定の行・列への `Click` で該当する単位を操作できます。ブロックが折りたたまれた際、ウィンドウはその単位が元あった行位置に留まります。ウィジェットとしての `viewer` は各種キー（矢印キー, Page Up/Down, Home/End, マウスホイール, `n` と `p`, Enter または Space, `-` と `+`）を受け付けます。`mouseMsg top left` は、ウィンドウの左上隅がそのセルにある場合のマウスメッセージを生成します。セグメントにはMarkdownテキスト（`addSegment`, `extendSegment`）だけでなく、プログラム側から渡した段落も使用できます。`addStyled` は `StyledText` をそのまま受け取り（Markdownでは表現できない独自のスタイル、ぶら下げプレフィックス、折り返しをそのまま保持。`Styled` ブロック）、`extendStyled` は最後の段落の末尾にスパンを追加してその段落のみを再折り返しし、`addDoc` は幅から `StyledText` への関数を受け取って幅の変更時に再生成します（`StyledDoc` ブロック）。テーマの `fold` 設定でこれら（`KStyled`）を折りたたみ可能にするかを指定できます（既定では折りたたみ不可）。折りたたみやカーソル移動は影響を受けるセグメントのみを再レイアウトし（後続行は移動のみ）、幅の変更や `FoldAll` は全セグメントを再レイアウトします。

## 言語モデルとのチャットの例

`examples/LlmChat.idr` は、`web` パッケージの `OpenAIStream` を使って OpenAI chat completions API 互換のサーバー（LM Studio, llama-server, Ollama など）と通信するデモです。質問は `RunTaskAs "chat"` で送信され、返答はメッセージごとに1チャンクずつ読み込まれます。タスクは `Opened stream` で完了し、`update` が次のチャンクを取得する次のタスクを開始します。届いたチャンクは `MarkdownView` の最後のセグメントに追加されます（`extendSegment`）。各メッセージが1つのセグメントとなり、見出し `# ai` または `## you` とその本文がMarkdownとしてパースされるため、更新時はそのセグメントのみが再パース・再レイアウトされます。コードブロック、引用、リスト、あるいはメッセージ全体を折りたたむことができます（左カラムのマークをクリックするか、Alt+Up / Alt+Down で選択して F2 キーを押す。F3/F4 で一括開閉）。モデルが回答の前に出力する思考プロセス（reasoning）は非表示にされます。チャンクの受信待ちの間も端末は操作可能であり、応答の生成は `CancelTask "chat"` で中断できます。質問を送信するたびに会話履歴全体が送信されます。入力欄は `TextArea` であり、Enter で送信、Alt+Enter（改行を含む貼り付けも同様）で新しい行を挿入します。エディタの高さは入力行数に応じて自動伸縮し（`TextArea.wrappedRows`、最大8行）、ログ表示部が残りの画面領域を占有するため、編集やリサイズのたびに両者のサイズが再計算されます（`layoutFor`）。ログ表示部はフォーカス可能要素ではありません。入力欄のみがフォーカスを持つため、文字を入力する際に Tab を押す必要がなく、Page Up/Down（エディタのキーハンドラからログへ委譲）やマウスホイール操作は直接ログ表示部に届きます。接続先URLやモデル名はコマンドライン引数（`--url`, `--model`, `--system`）または環境変数（`$LLM_URL`, `$LLM_MODEL`, `$LLM_API_KEY`）で指定でき、URLは `http` と `https` の両方に対応しています（`web` の `endpointUrl`）。

## 差分出力

ペインターはビューの描画ごとに新しい `Frame` へ書き込みを行い、`diffFrames` が直前のフレームとセル単位で比較します。

- 変更があったセルのみが書き出されます。カーソル移動エスケープシーケンスは、次に変更するセルが現在のカーソル位置と異なる場合のみ出力されます。SGR（装飾）シーケンスは、直前に書き込んだセルとスタイルが異なる場合のみ出力されます。
- SGR シーケンスは常に「リセットして設定」（`ESC[0;...m`）という形式をとります。若干のバイト数増加と引き換えに、端末の状態不整合を防ぐ堅牢性を得ています。
- スクロールした行は、端末自身のスクロール機能を使ってスクロールさせます。出力が 192 文字以上になる場合、新フレームの各行と旧フレームの各行が比較されます（スクロールバーの有無で判定が狂わないよう最終列を除いた行のハッシュ値を比較。結合文字は除外。空行はカウント外）。3行以上が上下に移動している場合、スクロール領域（`CSI top;bottom r`）とスクロールコマンド（`CSI n S` または `CSI n T`）、および領域リセットを用いた出力が試行され、その後に現在の端末表示と依然として異なるセルのみが書き出されます。最も多くの行が一致する2種類の移動量が試され、それぞれ最長の連続行のみがスクロールされ、それらと通常のプレーンな差分出力のうち最も文字数の短いものが採用されます。そのためスクロール機能を使った出力が通常の差分出力より長くなることはありません（147 × 33 の画面でテキストが1行スクロールした場合、通常の差分なら 4274 文字かかるところが 159 文字で済みます）。スクロールによって新しく現れる行は空白行となり（端末は `ESC[0m` 適用後に既定の背景色で埋めます）、差分は行を移動させて新しい行を空白にした旧フレーム（`Frame.shiftRows`）に対して取られるため、最終的な描画結果はスクロールを使わなかった場合と完全に一致します。スクロール領域は画面の全幅に及ぶため、スクロールした行の左右にある変化したセル（スクロールバーや境界線など）は正しく再描画されます。
- 直前のフレームが存在しない場合や画面サイズ変更の直後は、まず画面全体が消去され、空白デフォルトセルに等しいセルはスキップして描画されます。
- 画面の最終列への書き込み後は、カーソル位置が未確定（端末の自動折り返し待ち状態）とみなされるため、次回の書き込み時は必ずカーソル再配置が行われます。

## ランタイム

`openTerminal` は標準入力を raw モード（`cfmakeraw`, `VMIN=1`）に設定し、代替画面への切り替え、カーソルの非表示、bracketed paste（ブラケット付き貼り付け）の有効化を行うエスケープシーケンスを書き込みます。`closeTerminal` はこれらすべてを元通りに復元します。raw モードでは `ISIG` が無効化されるため、Ctrl-C はシグナルではなくキー入力（`Ctrl+KChar 'c'`）として届き、プログラム側でその扱いを決定できます。

`newLoop` は `openTerminal` の前に呼び出されます。呼び出し元スレッドで SIGWINCH, SIGINT, SIGTERM, SIGHUP, SIGPIPE, SIGCONT, SIGTTOU, SIGTTIN をブロックし、signalfd 経由でそれらを読み取ります。端末入力および `addTimer`/`addOneShot` による timerfd と合わせ、単一の epoll で一括待機します。`waitEvents` は発生したイベントを値として返します: `EInput`, `EResize`, `ETimer`, `ETerminate`（ウェイクアップ1回につき最大1つ）, `EResume`（SIGCONT）, `EEndOfInput`（入力が閉じられたかエラー。SIGPIPE は破棄されるため、出力が閉じられた場合はプロセスが強制終了されるのではなく書き込み失敗として現れます）。0 ms のタイマーは 1 ms 後に発火します（すべて 0 の timerfd 値はタイマー解除を意味してしまうためです）。

入力バイト列は、純粋なインクリメンタルパーサーである `parseInput` によってデコードされます。後続バイトが続く可能性のあるバイト列（単独の ESC、途中で切れた CSI、途中で切れた UTF-8 文字）は次回の読み込みまで保持されます。そうした未完了の末尾バイト列が存在する場合、ループは内部で 30 ms のワンショットタイマーをセットします。これにより、タイマーやシグナルでループが忙しい場合でも、入力が途絶えて 30 ms 経過すれば単独の ESC は Escape キーとして確定されます（不完全な CSI はその時点で破棄されます）。不正な UTF-8 シーケンスは U+FFFD に置換され、継続バイトでない次のバイトからデコードが再開されます。ブラケット付き貼り付けはループ自身によって蓄積され（末尾の終了シーケンスが読み込み境界をまたいでも検出できるよう、末尾5バイトを保持しながらチャンク単位で処理されます）、タイマーによって途中で切断されることはありません。未知のシーケンスは破棄されます。

終了処理: まず `closeTerminal` を呼び出し、その後に `closeLoop` を呼び出します。`closeLoop` はシグナルのブロックを解除する前に、保留中のシグナルを回収します。ループを作成したスレッドでブロックされたシグナルはそのスレッドには届きませんが、ループ作成前に開始された他のスレッドには依然として既定のシグナル動作が適用されるため、ループは他のスレッドを開始する前にメインスレッドで作成してください。SIGKILL や SIGQUIT で強制終了された場合、あるいはプログラムがクラッシュした場合は、端末設定を復元することはできません。

外部から送信された SIGTSTP（`kill -TSTP`。raw モードではキーボードの Ctrl-Z はプレーンなキー入力になるため、端末から直接シグナルが送られることはありません）は他のシグナルとともにブロックされ、イベント `ESuspend` として読み取られます。ランタイムはこれを `Suspend` コマンドと同様に処理します。プログラムが一時停止する前に端末設定が復元されるため、シェルを正常に操作できます。

## プログラムモデル

`Program model msg` は、`init : (model, Cmd msg)`, `update : msg -> model -> (model, Cmd msg)`, `view : model -> Node msg`, `subs : model -> List (Sub msg)` から構成されます。`runProgram`（明示的なファイル記述子を使う場合は `runProgramOn`）は端末を開き、`init` のコマンドを実行した後、「画面描画 → イベント待機 → メッセージ変換 → `update`」のサイクルを繰り返します。`Quit` が発行されると端末を復元した上で最終的なモデルを返します。

- `Cmd`: `Quit`（終了）, `Emit msg`（即座にメッセージを発行）, `After ms msg`（指定ミリ秒後のワンショットタイマー）, `Perform (IO msg)`（今すぐ実行して結果をメッセージとして渡す。ループをブロックするため短時間の処理向け）, `Batch`（一括実行）。
- `Sub`: `OnInput`（フォーカスされたノードが処理しなかったキー入力や貼り付け）, `OnMouse`（後述のマウスイベント）, `OnResize`（画面サイズ変更。起動時にも1回通知される）, `Every key ms msg`（周期タイマー。`subs` が返すリストが変化した際に、文字列 `key` を識別子としてランタイムがタイマーの開始・停止・時間変更を行う。コンポーネントは購読を `scopeSub name` で包むことで他のコンポーネントとキーの衝突を防げる。同一スコープ内では1つのキーが1つのタイマーを表し、ランタイムは確認したすべてのキーを記憶するため、キーは有限の固定集合から選ぶべき）, `OnTerminate`（未指定の場合、SIGINT/SIGTERM/SIGHUP や入力の終了によってプログラムは終了する）。
- メッセージは送信された順序で、1回の `update` につき1つずつ処理されます。1つのイベントや `init` コマンドによって送信されたメッセージ（`Batch [Emit B, Emit C]`、あるいは1つのキーに複数の購読が反応した場合など）はまずキューに入れられ、それらの処理によって新しく生成されたメッセージはその背後に並びます（B, C の順で処理され、B が発行した `D` は C の後に処理されます）。`Perform` は即座に実行され、完了するまでイベントループをブロックします（シグナルの処理も待たされます）。`Quit` が発行された後は、バッチの残り、キュー内のメッセージ、および同時に届いたイベントはすべて破棄されます。
- `RunTask t` は、プログラムと並行して `Control.Task` のタスクを実行します（スケジューラは `control-async` の `Control.Task.Scheduler` であり、プログラムごとに1つ存在します）。タスクの完了時のメッセージは `Emit` と同様に配信され、タスクがファイル記述子、タイマー、他のタスクを待っている間も、`Perform` のようにイベントループが停止することはありません。スケジューラの `pollFd` はループの監視対象記述子の1つ（`watchFd`, イベント `EReady`）となり、タスクの開始、完了通知、タイマーの待機が発生した際に読み取り可能になります。その際ループは `turn sched 0` を呼び出します。タスクはイベントループのスレッド上で実行されます。ブロッキングの可能性がある処理は `Control.Task` の `blocking` を使って最大4つのワーカースレッドのいずれかで実行でき（ワーカースレッドは初回必要時に起動されるため、これを使わないプログラムはシングルスレッドのまま動作します）、その結果はタスクのメッセージとしてループに戻ってきます。`RunTaskAs key t` は、同じ名前ですでに実行中のタスクがあればそれを破棄してから新しいタスクを開始します。`CancelTask key` は実行中のタスクを破棄します（待機中の処理はキャンセルされますが、すでに開始されたステップの途中で割り込まれることはありません）。プログラム終了時にまだ実行中のタスクはそのまま破棄されます。
- `SetClipboard text` は OSC 52（`System.Console.Xterm`）を使ってテキストをデスクトップのクリップボードに格納します。端末がこれに対応しているかどうかを知る術はありません（tmux では `set-clipboard on` が必要であり、多くの端末で設定の有効化が求められます）。`A.copyText msg model` や `T.copyText msg model` は、`Copy` や `Cut` が取得しようとしているテキストを返すため、アプリケーション側では `A.update e` と並べて `maybe NoCmd SetClipboard (A.copyText e m.text)` のように処理できます。クリップボードの読み取り（端末への問い合わせ）は行いません。
- `Suspend` はシェルの Ctrl-Z と同様にプログラムを一時停止します。端末設定を復元し、プロセスグループ全体を SIGSTOP で停止させます（これにより `idris2 --exec` など親プロセスから起動された場合でも一緒に停止し、シェルからジョブの一時停止として認識されます）。再開（SIGCONT）されると再び raw モードに移行し、画面全体を再描画します。raw モードでは Ctrl-Z はキー入力になるため、これに対して `Suspend` を返すかどうかはプログラムが自ら決定します。外部から SIGSTOP で停止された後に届いた SIGCONT はイベント `EResume` となり、同様の復元処理を行います。停止中に端末サイズが変更されていた場合（停止中のジョブにはサイズ変更は通知されません）、再開時に新しいサイズが検出され `OnResize` が通知されます。
- コンポーネントの合成は Elm と同様に行われます。親コンポーネントが子コンポーネントのモデルを保持し、そのメッセージをラップします。`mapNode`, `mapCmd`, `mapSub` を用いて、子のビュー、コマンド、購読を親の中に埋め込みます。

### マウス

`Mouse` は `Input` の一種です。`MouseEvent` はボタン（`LeftButton`, `MiddleButton`, `RightButton`, `WheelUp`, `WheelDown`, `NoButton`）、アクション（`ButtonDown`, `ButtonUp`, `Drag`, `Move`）、左上を 0 とするセル単位の座標、修飾キーを保持します。SGR エンコーディング（`ESC [ < code ; column ; row M/m`）からデコードされます。マウス報告（`?1002h` および `?1006h`）は、何らかの `OnMouse` 購読が存在する間だけ有効化されます。有効にすると端末自身のテキスト選択機能が奪われてしまうためです。購読がなくなったり端末が閉じられたりすると無効化されます。マウスイベントは `OnMouse` 購読に送られ、`OnInput` に届くことはありません。

`MouseFocus` も購読の一種です。マウス報告を有効化し、ランタイムがマウスを用いてフォーカス制御を行えるようにします。描画のたびにレイアウト情報が保持され、各フォーカス可能ノードの配置領域が記録されるため、ランタイムはどこにどの要素があるかを把握できます。左クリックによってポインタ下のフォーカス可能要素（最も内側の要素、あるいは重なり合っている場合は後から描画された要素）へフォーカスが移動します。またフォーカス可能要素の領域上で発生したすべてのマウスイベントはその要素のハンドラにも渡され、その際座標はそのノードの左上を基準とする相対座標に変換されます。これにより各ウィジェットはどこがクリックされたかを判定できます（`Select` はクリックされた行を選択しホイールを上下移動として扱い、`TextInput` や `TextArea` はポインタの位置にカーソルを移動させます）。

左ボタンの押下には `clicks`（連続クリック回数）も付与されます。ランタイムは同一セル上で 400 ms 以内に連続して行われたクリックをカウントし（`countClick`、純粋関数としてテスト済み）、1, 2, 3, そして再び 1 と番号を付けます（他のイベントは 1 です）。`TextInput` と `TextArea` はダブルクリックで単語を選択し、トリプルクリックで行（`TextInput` の場合はテキスト全体）を選択します。

`MouseEvent` の座標は、`OnMouse` では画面絶対座標、ハンドラ内ではノードの左上からの相対座標になります。フォーカス可能要素の領域は可視部分（祖先要素によってクリップされた範囲）に切り詰められ、描画のたびに更新されます。そのためレイアウトを変更するイベントと同じバッチで届いたクリックは、直前の描画時のレイアウト情報に基づいて判定されます。

### 端末カーソル

画面描画中はカーソルは非表示にされますが、入力メソッド（IME）は直前に置かれていたカーソル位置に変換候補ウィンドウを表示するため、ランタイムは描画後にカーソルを適切な位置へ配置します。`cursorHere` の印が付いた箱がその位置を指定します。フォーカスされた `TextInput` は自身のカーソルセルにこの印を付け、そこに端末カーソルが表示されます（画面上にも反転セルが描画されます）。そうした箱がない場合、カーソルは非表示のまま画面左下に退避されます。カーソル位置のエスケープシーケンスは、位置または画面内容が変化した場合にのみ送信されます。

### フォーカス

ビューはノードに `focusable (\focused => node) handler` を指定してマークを付けます。ランタイムは木構造順にフォーカス可能要素に番号を割り当て、現在フォーカスされている要素のインデックスを保持し（ビューの変化時に範囲内にクランプされます）、対象の要素だけ `focused` を True に設定してビューを再構築します。キー入力はまずフォーカスされているノードのハンドラに渡されます。ハンドラが `Nothing` を返し、かつキーが Tab または Shift+Tab である場合、フォーカスが次/前の要素に移動します（末尾から先頭へ循環します）。それ以外の場合、キーは `OnInput` 購読に渡されます。Tab キーを自身で処理したいハンドラ（エディタなど）は、Tab に対して `Just` を返します。

ハンドラは各イベントの後にビューから再構築されるため、ハンドラは常に直前のイベントによって生成された最新のモデルを参照できます。フォーカスはインデックスで管理されます。フォーカスされている要素より手前に新しいフォーカス可能要素が現れたり消えたりした場合、現在そのインデックスを持つウィジェットにフォーカスが移動します（要素数が減った場合は末尾にクランプされます）。`keyed "name" widget` を使うとノードの先頭にあるフォーカス可能要素に名前を付けることができ、ランタイムは現在フォーカスされている要素のキーを記憶します。ビューが変化した際、フォーカスはそのキーを持つウィジェット（木の中のどこに移動していても）へ追従します（キーが見つからない場合はインデックスによる管理に戻ります）。キーは木構造順に検索されるため、各要素には一意なキーを割り当ててください。

画面はイベントのバッチごとに再描画されます。差分エンジンにより、描画コストは変更された領域の大きさに比例した低コストに抑えられます。書き込みが失敗した場合、次回の描画は画面全体の完全再描画となります。

## ウィジェット

ウィジェットは Elm の意味でのコンポーネントです。すなわち `Model`, `Msg`, `update`, そして各種のビュー関数から構成されます。状態を持つウィジェット（`TextInput`, `Select`）は `keyMsg : Input -> Maybe Msg` を持ち、ビュー自身を `focusable` で包んで提供します。そのため親コンポーネントは以下のように記述するだけで済みます。

```idris
T.field Edit (Just Add) model.input   -- Edit : T.Msg -> AppMsg, EnterでAdd
```

これにより、フォーカス管理、キー入力処理、カーソル描画が自動的に行われます。ウィジェットが処理しないキー（Tab, Altキー, Ctrl-C, Esc など）はフォーカス移動や `OnInput` 購読に委ねられます。Enter キーはウィジェットが持つ `submit` メッセージ（設定されている場合）に送られるため、入力欄がフォーカスされている間は入力欄の Enter が `OnInput` に届くことはありません。

### TextInput（1行テキスト入力欄）
文字挿入、Backspace, Delete, 矢印キー, Home/End, Ctrl-A/E/B/F/K/U/D, 貼り付けに対応しています。Shift + 左右矢印/Home/End やマウスのドラッグで範囲選択ができます（文字入力、Backspace, Delete, 貼り付けによって選択範囲が置換されます）。Alt-A で全選択、Alt-W でコピー、Ctrl-W で切り取り、Ctrl-Y でモデルが持つクリップボードからの貼り付けができ、Ctrl-_ / Ctrl-^ で Undo / Redo が行えます（連続した文字入力は1つのアンドゥステップとしてまとめられます）。改行やタブはスペースに変換され、その他の制御文字は破棄されます（`fromString` でも同様です）。モデルは入力欄の幅とスクロール量を把握しているため、カーソルが入力欄からはみ出す場合にのみテキストがスクロールします。幅はセル単位で計算されます（全角文字は 2 セル、結合文字は 0 セル）。カーソルは反転セルとして描画されます。幅 0 の文字の上にある場合は空白の反転セルになります。書記素クラスタ（grapheme cluster）の合成は行われないため、カーソルは各結合文字の上を個別に移動します。

### TextArea（複数行テキストエディタ）
現在の行に対して `TextInput` と同様のキー操作が行えます（Ctrl-A/E/K/U で行頭/行末への移動や削除）。Enter で改行、上下矢印キーで短い行をまたいでも桁位置（セル単位）を維持した移動、PageUp/PageDown（カーソルとともに表示ウィンドウを1ページ分移動）、Ctrl-Home/Ctrl-End、行を結合する Backspace と Delete、改行を含む貼り付け（CR LF および単独の CR は1つの改行として扱われます）、マウス操作に対応しています。既定では行の折り返しは行われません。ビューは必要最小限だけ水平・垂直方向にスクロールし（画面に収まる行は先頭から表示されます）、右端にスクロールバーが表示されます（スクロールバーの列はクリックを無視します）。`setWrap True` を指定すると、長い行を折り返して複数行（row）として表示します（収まる最後の空白、空白がなければ幅の尽きる位置で折り返されます。行いっぱいの直後にある空白は行末にぶら下がります）。折り返し時の行幅は、スクロールバーおよび行末カーソルのためにエディタの幅より 2 セル狭くなります。このとき上下矢印キーや PageUp/PageDown は折り返された行単位で移動し桁位置を維持し、クリックやドラッグも折り返し行の位置に着地します。Home/End, Ctrl-A/E, Ctrl-Home/End は論理行およびテキスト全体を基準に動作します。表示ウィンドウは `top`（論理行）と `topRow`（その中の折り返し行）で管理され、スクロールバーは論理行数を数えます。モデルは総行数と現在のカーソル行を保持しているため、通常の文字入力、Enter、矢印キー、Backspace、Delete の計算コストはテキスト全体ではなくカーソル行の長さに比例します。選択範囲の置換、切り取り、貼り付け、全選択、Ctrl-Home/End、ページ送り、およびカーソル行から遠く離れた場所のクリックはテキスト全体のサイズ（または移動距離と行長）に比例します（`value` や `selectedText` も同様です）。`resize` で表示ウィンドウのサイズを変更できます。結合文字はテキスト内に保持されセル幅は取りません。描画は行われません（端末に合成を要求できないためです）。

- **選択（Selection）**: Shift + 移動キー（矢印キー, Home/End, PageUp/PageDown, Ctrl-Shift-Home/End）または左ボタンドラッグで選択範囲を広げます。Alt-A で全選択します。文字入力、Enter、貼り付けは選択範囲を置換し、Backspace, Delete, Ctrl-K, Ctrl-U は選択範囲を削除します。Shift なしの移動キーで選択は解除されます。選択されたセルは青い背景で描画され、カーソルは反転表示されます。
- **クリップボード（Clipboard）**: Alt-W でコピー、Ctrl-W で切り取り、Ctrl-Y で貼り付けを行います。エディタ専用のクリップボードを使用します（`clipboard` で内容を読み取れるため、端末側のクリップボードへ渡すことも可能です）。端末側からの貼り付けはブラケット付き貼り付けとして届きます。
- **取り消し（Undo）**: Ctrl-_ で取り消し（Undo）、Ctrl-^ でやり直し（Redo）を行います。連続した文字入力、連続した Backspace、連続した Delete はそれぞれ 1 ステップとして記録されます。カーソル移動を行うと新しいステップが開始されます。選択範囲の置換は独立した 1 ステップとなります。内容を変更しない編集（先頭での Backspace や空の貼り付けなど）は履歴に影響を与えません。新しい編集を行うと Redo 可能な履歴は破棄されます。最大 100 ステップまで保持されます。Ctrl-Z はアプリケーション側に委ねられています（editor や llmchat のサンプルでは Suspend に割り当てられています）。
- 垂直移動の桁位置はセル単位で計算され、クリックやドラッグによってカーソルはそのセルの位置に配置されます。

### Scroll（読み取り専用スクロールビュー）
ウィンドウ内で複数行のテキストをスクロール表示する読み取り専用ビューです。矢印キー, PageUp/PageDown, Home/End, マウスホイール（1ノッチあたり3行）でスクロールし、右側のバーが表示位置を示します。`ScrollBar.scrollBar` はスクロールバー単体の部品です。

### LogView（追記型ログビューア）
末尾に追記されるスタイル付きテキスト（`StyledText`）を表示します。折りたたみがなく段落間に空行が入らないように設定された `MarkdownView` 上の薄いラッパーであり、`Scroll` と同じキー操作とスクロールバーを持ちます。チャットやゲームのメッセージ表示に適しています（`examples/Chat.idr` や `examples/LlmChat.idr`）。`append` は新しい段落を一度折り返して行シーケンスに保持します。`extendLast` は最後の段落の末尾にスパンを追加し（1語ずつ届くストリーミング応答など）、その段落のみを再折り返しします。追記・拡張・表示のコストは「新しいテキスト、最後の段落、表示ウィンドウ」にログ長の対数を掛けた程度に収まります。幅が変更された場合にのみ全体が再折り返しされます。ログの長さに上限はありません。ウィンドウが最末尾にある間は新しいテキストの追加に自動で追従します。上にスクロールすると自動追従は一時停止し、再び末尾までスクロールすると（End キーや下スクロール）追従が再開されます。幅は高さと同様にモデルの一部として保持されるため（`empty rows width`, `resize rows width`。テキストはバーの幅を引いた幅に折り返されます）、プログラムは `OnResize` から得たウィンドウサイズを渡します。

### Table（スクロールテーブル）
固定ヘッダーと、`Scroll` と同様にスクロールする本体（同じメッセージとキー操作）を持ち、本体の右側にスクロールバーが表示されます。`Display.table` は静的なバージョンで、`Display.tableRow` はそれぞれの1行を表します。

`Select`, `Scroll`, `LogView`, `Table`, `TextArea` の表示ウィンドウの高さはモデルの一部です（`fromList rows ...`, `resize rows`）。そのため `update` と `view` で異なる高さを与えることはできません。

### Select（スクロール選択リスト）
上下矢印キー, PageUp/PageDown, Home/End, 行のクリック（最終項目より下のクリックは無視されます）, マウスホイールで操作し、選択項目に追従してウィンドウがスクロールします。選択中の行はフォーカス時は反転表示、非フォーカス時は `>` マークで示されます。右側にスクロールバーが配置されますが、キーやクリックを受け付ける領域の外側に置かれます。Ctrl, Alt, Shift を伴うキーは受け付けません。`setItems` は選択位置を可能な限り維持し、`resize` でウィンドウの高さを変更できます。

### Checkbox, Button（チェックボックスとボタン）
- `checkbox label checked toggle`: `[x] label` または `[ ] label` を描画し、Enter, Space, クリックで `toggle` メッセージを送信します。Bool 値は親コンポーネントが保持します。フォーカス時は枠が反転表示されます。
- `button look label press`: ボタンを描画します。`look` は `Framed`（角丸の枠線。フォーカス時は太枠）、`Flat`（グレー背景）、`Link`（下線付きの明るい青色、ハイパーリンク風）から選べます。フォーカスされたボタンはラベルが反転表示され、Enter, Space, クリックで `press` メッセージを送信します。
- どちらもテキスト幅に合わせたサイズとなり（行内に並べて配置できます）、Ctrl や Alt を伴うキーはアプリケーション側に委ねられます（`Activate.activates`）。

### MenuBar（ドロップダウンメニューバー）
タイトルが並ぶバーとドロップダウンメニューを提供します（`menuBar wrap model`）。`Menu` はタイトルと `Entry` のリスト（`Item label msg` または `Separator`）を持ちます。バーは親要素の左上に配置されるフォーカス可能な `absolute` 箱であり、開かれたメニューとともに通常のフローに乗るため、メニューは下層のコンテンツの上に重なってドロップダウンします。箱は子要素をクリップするため、親要素は画面全体の高さを持つ必要があります（ビューのルート、または画面と同じ高さの箱）。アプリケーション側は最初の1行を空けておきます。左右矢印キーでタイトル間を移動し、下矢印キーでメニューを開きます（開いた後は上下矢印キーで項目間を循環移動し、セパレータはスキップされます）。Enter または Space でメニューを開くか項目を決定し、Escape で閉じます（何も開いていないときはアプリケーション側に委ねられます）。タイトルをクリックするとメニューが開閉し、項目をクリックするとその項目が選択され、メニュー枠内のその他の場所をクリックするとメニューが閉じます。メニューはフォーカスを持っている間だけ開いた状態で描画されます。`update : Msg -> Model msg -> (Model msg, Maybe msg)` は選択された項目のメッセージも返すため、アプリケーション側はそれを `Emit` で送信します。

### KeyGuide（ファンクションキーヒント行）
`F1 Help  F2 Save` のようにファンクションキーのヒントを並べた行を表示します（キー部分は反転表示）。`MkHint fkey label msg` のリストを渡すことで行を描画し（`keyGuide`）、メッセージを返します。この行自体がマウスの左ボタンを受け付けます。ヒントをクリックするとそのメッセージが送信され、ヒントとヒントの間の空白をクリックしても何も起きません。キー入力自体は受け取らないため Tab キーを押すとフォーカスは次の要素へ移動しますが、フォーカス可能要素であるためフォーカス循環の1つの停止点となります。実際のキー入力処理はアプリケーション側で行います。`OnInput` 購読で `keyInput hints` を使うと、Fキー入力を対応するヒントのメッセージに変換できます（Ctrl, Alt, Shift を伴うキーは除外されます）。`keyClick hints column` はクリック位置からヒントを検索する関数であり、独自のマウス購読を行う場合に使用できます。

### TabStrip（タブバー）
` One │ Two │ Three ` のようにタブを並べて表示し、1つのタブがアクティブになります（フォーカス時は反転表示、非フォーカス時は太字と下線）。左右矢印キー, Home/End, クリックでタブを選択できます。タブバーはどのタブがアクティブであるかを管理し、中身の表示はアプリケーション側が担当します。`tabbed wrap model contents` を使うと、タブバーの下にアクティブなタブの内容を表示する枠付きペインを自動的に組み合わせて表示できます。箱の幅を超えるタブバーは端で切り詰められます。アクティブなタブは `Fin (length titles)` で表されるため、最後のタブを超えることはありません（`activeIndex` で取得、`select` で設定し末尾にクランプされます）。タブバーは最低1つのタブを持つ必要があります。

### Splitter（境界可動スプリッター）
2つのペインとその間の仕切り線を提供します。左右分割（`LeftRight`）または上下分割（`TopBottom`）が可能です。第1ペインが `size` セル（`lo` から `hi` の間）を占有し、第2ペインが残りの領域を占有します。仕切り線は幅1セルのグレーの帯で、フォーカス時は青色になります。分割方向に沿った矢印キーで1セルずつ移動でき、マウスでドラッグして動かすこともできます。フォーカス可能要素は自身の領域上のマウスイベントしか受け取れないため、仕切り線をドラッグしている間はスプリッター全体を覆う透明なカバーが代わりに配置され（同じキーを保持）、ポインタの位置を新しいサイズに変換します。Escape キーを押すかマウスボタンを離すとドラッグが終了します。スプリッターの外側でマウスボタンが離された場合、カバーには届かないため、ドラッグ中（`held`）は `OnMouse (map wrap . releasing model)` を購読してください。マウス報告（`MouseFocus`）が必要です。各スプリッターには一意な `name` を指定してください。サイズは `lo` に `Fin (S span)` を足した形式で管理されるため、モデルをどのように操作しても常に `lo` と `hi` の間に収まります（`size` と `hi` で取得可能）。

### Display（表示専用パーツ）
- `spinner tick`: アニメーションスピナー（`Every` 購読から `tick` を進めます）。
- `progressBar cells percent`: 指定セル幅のプログレスバー（折り返されることはありません）。
- `table columns rows`: 静的なテーブル（セルは列幅で切り詰められ、不足セルは空、余剰セルは破棄されます）。

`examples/Demo.idr` は入力欄、リスト、各種表示ウィジェットを組み合わせたデモです。`examples/Editor.idr` はヘルプビューアを備えた小さなエディタです。
